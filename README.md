# 销售标准管理 · CRM 项目章程（路线 B：TS + NestJS 全栈）

> 本文档是 AI 协作开发的"交通规则"。每次让 AI 改代码前，先读它。
> **本文只管「文档治理」**（Git 约定 / L0·L1 联动 / 归档规则 / 权威落点总表 / 目录与归类规则）；**「AI 行为与经验」见《技术决策/AI协作铁律与踩坑复盘》**。两者重叠处**只写指针、不复述**。

## 一、技术栈定案

- **后端**：NestJS 12（Node + TypeScript）+ MySQL 8 + Redis
- **前端**：Vue 3（TypeScript）+ Vite + **Ant Design Vue**（ⓘ「Ant Design **5**」指**设计基准 token**，见《销售CRM设计规范》；库版本以 npm `latest` 为准）
- **全栈统一语言 / 类型**：前端与后端共用一套 TypeScript 类型，来源是后端 OpenAPI（Swagger），由 `openapi-typescript` 生成到 `前端/src/api/types.ts`。**禁止手写对接、禁止前后端各维护一份接口类型**（双真相源是 AI 出错重灾区）。
- **ORM = Prisma**：① 类型安全最强，**AI 写错字段 / 类型时编译即报错**，最契合本项目的 AI 协作方式；② 全部表结构集中在**一个 `schema.prisma`**，可直接与《数据架构文档》逐行对账；③ 复杂报表查询可用 `$queryRaw` 兜底。代价：MySQL 生成列与分区表需手写 migration（口径见《数据架构文档》§十五「Prisma 落库口径」＋ `服务端/prisma/README.md`）。
- **数据库为唯一真相源**：DB 约束（唯一索引、CHECK、生成列）兜底业务不变量；应用层只做"友好提示"，不替代约束。

## 二、抑制 AI 错误的四道闸（按杠杆排序）

1. **数据库约束兜底**：唯一索引（撞单 / 激活冲突）、CHECK（审批人≠申请人）、生成列（`active_key`）。→ 挡"撞单、重复激活、自批"。
2. **类型安全贯穿前后端**：后端 DTO（class-validator 运行期校验）+ 前端 TS + OpenAPI 生成共享类型。→ 挡"字段拼错、枚举乱传、接口错位"。
3. **自动化测试当护栏**：每条业务铁律写单测 / 集成测。→ 挡"公海规则、掉海判定、状态机错乱"。
4. **人工 SME 复审闸**：关键模块（业绩 / **合同业绩分配** / 掉公海 / 脱敏）上线前由七叔走查关键流程。→ 挡"逻辑语义错"（类型与测试都挡不住这类）。

## 三、Git 使用约定（提交即还原点）

- **本地单线**：直接在 `main` 上提交，**不切 feat / dev 分支**。
- **阶段性提交**：每完成一个独立阶段（一个模块 / 一次修复 / 一次文档调整）做一次提交，提交信息写清"改了什么、为什么、联动哪几份文档"。
- **还原保障**：每个提交都是可回退节点 —— 回上一个节点 `git reset --hard <提交号>`；只撤某次错误提交 `git revert <提交号>`；`git log` ＝ 开发过程汇总。里程碑 / 大版本可打 tag（如 `v0.1-mvp-org`）。
- **多窗口并行**：**禁用 `git add -A` / `git add .` / `git commit -a`**，提交前必跑 `git status --short` 逐文件认领（细则 →《AI协作铁律与踩坑复盘》§一 E）。
- 将来接远程仓库 / CI 再严格走分支，到时再说。

## 八、需求变更全文档对齐规则（铁律）

> **★ 第 0 步**：**动任何文档前，先读《废止口径登记表》**（需求规格/）—— 所有被后续拍板推翻的旧口径集中登记在那儿。文档正文若仍出现旧说法，**以登记表为准**（**条数以该表实数为准**）。

**触发**：任何需求变更（新增 / 修改 / 删除功能、字段、流程、规则），经七叔确认后生效。

**对齐动作（强制）**：变更确认后，必须同步审视并修订**所有相关文档**，不允许"只改一处、别处漂移"。

> ### ★ L0 变更联动铁律（最高优先级）
> **业务需求一改，下游三份必须同批跟着改；四份没同步，这次变更就算没做完。**
> 1. 一次变更 = 一张变更单：写清改了哪条规则 + 影响哪些表 / 字段、接口、页面
> 2. **先改需求文档，再改下游**；下游不得私自定义业务规则，冲突一律回改需求文档
> 3. 受影响文档**同批升版**，并**在同一次 git 提交里改完**（提交信息写清"改了什么 / 为什么 / 联动哪几份"）—— **文档内不再保留「修改记录」章节**
> 4. 需求改了但下游没跟上的，记为"进行中"，**不得标记已落地**
> 5. 被推翻的规则标"已废止 + 日期 + 替代规则"，保留原文一行，**停用不删**

> ### ★ L1 单一事实源铁律
> **同一事实只在四份文档中的一处定义一次；其余只写"见《业务需求文档》§X"，绝不复制一遍。**
> 业务规则 → 只在需求文档；表字段 → 只在数据架构；枚举业务含义 → 需求文档，物理编码 → 数据架构字典。

> ### ★★ 唯一权威落点总表（专治 AI"读串 / 读错"）

4. **校验**：变更落地后，重新跑一次**机械扫描**（grep 被推翻旧词 / 旧版本号 / 旧文件名）＋「需求一致性核查」，确认无新漂移后在 `main` 提交（不切 dev 分支；废止口径登记见《废止口径登记表》）。

   - **★ 新增负面约束必须补进 §十六**：动作＝正文新写一条"不做 X"，**同批**补一行进 §十六（漏收即等于放行）。

> 目的：让"同一事实在任意文档只有一种说法"，避免开发按过期描述实现。

> ### ★ 为什么文档内不再保留「修改记录」
> **原因**：文档内每一行版本记录，都以**"当时的规范口吻"存放已被推翻的说法**。这些历史行与正文并存 —— **AI 按关键词命中，读到旧行就照旧行写**。换言之，**文档内版本史本身＝一座旧口径仓库**，与 §八.4 机械扫描的清理目标直接相悖。
> **替代**：版本沿革的**唯一落点＝ git**（且比文字记录更精确：`git show <commit>` 给完整 diff）。
> **连带前提**：因此**每次改文档必须提交**（否则沿革断档）—— 见 §三 L0 铁律第 3 条。
> **原 7 份文档的修改记录全文**可在删除提交的**父提交**中完整取回 —— `git show <删除提交>^:<文件路径>`（或 `git log -p -- <路径>`）。
> **例外**：**需求 §十六 予以保留**，并改造为《**否决与后置清单**》—— 只留"不做 / 已砍 / 后置 / 不是那样"类负面约束（正文只写"做什么"，永不写"没做什么"，是 AI 防走偏的必需防线）。**其定位由「索引·非规范」升级为「★ 规范级」**：凡列于该表的一律不做，且**必须收全**（"表里没有"才代表"允许"）。

## 十、文档时态与状态规则

**核心原则**：用"文档位置"作为唯一时态信号 —— **现行有效文档留在用途目录，过去时 / 被取代文档移入根目录 `归档/`**。四个用途目录里只该看到进行时文档。

> 本规则能成立，依赖 §九 铁律②：文档间以"标题 + 版本号"互引、不依赖路径。因此把文档挪到 `归档/` 不会断任何引用 —— 两条规则配套。

**四态定义**：

| 状态 | 位置 | 含义 |
| --- | --- | --- |
| 草稿 | 用途目录（标题注明「草稿」） | 未确认，可能大改 |
| 现行有效 | 用途目录 | 当前生效，被引用为真相 / 依据 |
| 已归档·历史 | `归档/<用途>/` | 功能作用已完结，备查不常用 |
| 已废弃·被取代 | `归档/<用途>/` | 被新版取代，地图标注取代者 |

**归档触发（铁律）**：

1. **不自动归档，绝不因"放着久了"归档。**
2. 当某文档的"功能作用"已完成（如：方案对比已出决策、一致性核查的整改已落地），**AI 主动提问"是否归档"，由七叔拍板**；确认后才挪入 `归档/`。
3. 出现新版本取代旧版时同理，确认后旧版入 `归档/` 并在地图标注"被《新文档 Vx》取代"。
4. 归档 = 移动，**绝不删除**；移动后引用按 §九 铁律② 自动成立，无需改链接。
5. **★ 归档件必须加"已作废"头标 + AI 检索默认排除 `归档/`**：归档件文件名常与现行文档**近乎同名**，**AI 检索极易命中旧口径**。故：① 每份归档文档头部统一加 `> ⚠ 已作废，勿引用（现行见《xxx》Vx）`；② AI 检索（grep / glob）**一律排除 `归档/` 目录**，除非明确要求查历史。
   - **★ 机械强制已落地**：根目录 **`.ignore`** 内含 `归档/` —— **ripgrep（AI 检索底层）默认即跳过归档**，不再依赖"AI 自觉排除"。需要查历史时临时用 `--no-ignore` 或直接指定 `归档/` 路径。
   - **★ 为何不改名 `_归档/`**：现行文档中有 **30+ 处**以 `归档/...` 字面路径引用归档件；改名会把这些权威引用一次性变旧，**反而新增残留**。故改采 `.ignore` 机械隔离 —— 同样达到"检索不误命中"，且**零引用破坏**。归档目录名保持不变。
