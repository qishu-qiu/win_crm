## 通用规则
1. 纯静态 HTML + 少量内联演示 JS（Tab 切换、弹窗显隐可用极简 JS）；不引外部框架/CDN；图标用 emoji 或 CSS。

3. 所有页面引用：`../assets/style.css`（pages/ 目录下）或 `./assets/style.css`（根目录）。
4. 每页 `<title>` 按需求文档定义；页面右上角顶栏统一。
5. 股票/业绩涨跌配色遵守中国习惯：**涨红跌绿**（.up 红 / .down 绿，style.css 已定义）。
6. 每页底部加一个"设计说明"折叠注释块（HTML 注释即可），列出本页对应需求文档章节与关键交互点，供开发对照。

# V3.0 新增规范（2026-09-05）

## 一、可折叠侧边栏
- 含子菜单的一级项写法：`<div class="menu-group"><a class="menu-item has-sub" href="...">…</a><div class="menu-sub">…</div></div>`
- **默认收起**：`.menu-group` 上加 `collapsed`；当前页所在分组**不加** `collapsed`（展开）
- 箭头由 `app.js` 自动注入；折叠状态存 localStorage，刷新保持
- 一级项本身也可点击跳转（展开状态下点击才跳，收起状态点击仅展开）

## 二、顶部居中快捷入口
- 骨架中 `<span class="page-title">…</span>` 之后必须紧跟 `<div class="quick-bar"></div>`
- 内容由 `app.js` 渲染：默认 5 项（写跟进/新增预约/外出登记/录入客户/公海领取），末尾固定 `⚙` 跳 `profile.html`
- 最多 6 项；当前页对应的按钮加 `.on`
- **定位原则**：顶部快捷入口只放"动作型"（点击直接开弹窗或落表单），数据看板类入口放工作台

## 三、人员芯片（对接人 / 维护人 / 处理人）
```html
<span class="person-chip">            <!-- 详情/卡片：完整三件套 -->
  <i class="pc-avatar av2">张</i><span class="pc-name">张销售</span><span class="pc-role r-sales">销售</span>
</span>
<span class="person-chip mini">…</span>   <!-- 列表窄列：简版，角色 hover 浮层显示 -->
```
- **头像色 = 姓名哈希 12 色（`av0`~`av11`）**，不是角色色；同一人在全系统色一致
- 头像字 = 姓名首字；员工可上传自定义头像（个人中心/员工管理），上传后替代自动头像
- 角色类 `r-*` 只用于角色小标底色：`r-sales`(蓝) / `r-service`(青) / `r-delivery`(紫) / `r-manager`(橙) / `r-boss`(红) / `r-admin`(灰)
- **列表单元格一律用 `.mini`**（只显头像+姓名，hover 浮层显角色）；详情页/卡片用完整版；`.lg` 用于详情页大号
- 未指派时显示 `<span class="person-chip add">＋ 指派</span>`
- 哈希算法与真实系统一致：`sum(utf8 码位) % 12`（原型演示用，真实实现由后端按 user_id 下发）

## 七、一层抽屉 + 悬浮卡交互规范（V3.1，2026-09-08 新增，对应前端文档 V2.6 §4.3）

> 业务依据：原《前端页面开发需求文档》V2.6 §4.3（该文件已于 2026-09-09 归档至 `归档/V1.0档案库版本需求框架/`，**交互约定仍沿用**）。本规范约束"展示公司/联系人/销售"处如何做详情展开，**避免叠层抽屉**。

1. **一层抽屉铁律**：凡点公司名开抽屉（`.drawer`），仅此一层；抽屉内再点**业务线/业务关系** → 整页跳转 `/relation/detail/:id` 并关闭抽屉；再点**联系人/销售** → 悬浮卡（见 2/3），不叠第二层抽屉。
