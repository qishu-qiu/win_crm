## 二、项目概述

### 2.1 项目背景与目标

公司业务覆盖法律、财税、招牌网、线上营销（短视频/GEO/网站建设）、房产等多条业务线，均为销售驱动型。客户资料分散在个人手中，存在撞单、客户随销售离职流失、公海无人管理、跨业务线信息不通等问题。

前端目标：用一个统一 Web 端 CRM 落地"公司公海 → 部门公海 → 员工私海 → 业务关系"3 层映射模型，让销售、客服、交付、经理、总经理在同一系统完成获客、跟进、签约、交付、回访闭环。

### 2.2 设计主线：销售的一天

新菜单以**销售动线**为第一设计原则：

```
上班 → 数据看板（看预警/KPI）
     → 工作台（干活：写跟进/新增预约/外出登记/录入客户）
     → 预约管理（查：今天要赴的约、过期的约、没约的客户）
     → 业务关系（管：跟进中/已合作/已流失的客户盘子）
     → 公海（抢：领取无主客户）
```

### 2.3 页面归属模块、所属菜单、入口路径

左侧固定导航 + 顶部工具栏（消息铃铛、用户头像）。菜单结构（★=与 V1 相比新增，▲=调整）：

### 2.4 目标用户角色

| 角色 | 说明 | 高频页面 |
|---|---|---|
| 销售 | 一线获客、跟进、签约 | 工作台、预约管理、业务关系、公海、录入 |
| 客服 | 回访、续约维护（按部门配置启用） | 工作台、工单、台账、业务关系 |
| 交付 | 售后工单处理、台账维护 | 工单管理、客户台账 |
| 部门经理 | 本部门/管辖部门管理、审批、规则配置 | 全部 + 审批中心 + 高级搜索 + 系统设置 |
| 总经理 | 全公司视角（可管辖多部门） | 全部 + 全公司报表 |
| 行政 | 台账/财务只读 | 客户台账、合同管理（只读） |
| 游客 | 无公开页面，未登录一律跳 /login | /login |

## 三、整体业务需求说明

### 3.1 业务流程图（页面跳转逻辑）

```
登录 /login → 数据看板 /dashboard
   │ 点预警卡                │ 点"今日待跟进"
   ▼                        ▼
对应列表页（带筛选）      工作台 /workbench
                            │ 4 个快捷入口
              ┌─────────────┼──────────────┬─────────────┐
              ▼             ▼              ▼             ▼
         D1 写跟进      D2 新增预约    D3 外出登记    录入页 /entry/new
              │             │              │             │（手机号查重/公司匹配）
              └─────────────┴──────┬───────┴─────────────┘
                                   ▼
                     业务关系详情 /relation/detail/:id
                       │ Tab：基础/跟单/工作流/合同/工单/关系网
                       ├─[创建合同]→完善度校验→/contract/create→/contract/detail/:id
                       │              └不达标→/company/edit/:id（补全后回跳）
                       ├─[创建工单]→D11 抽屉→/workorder/detail/:id
                       ├─[转交/协同]→审批中心流转
                       └─[激活业务线]→唯一性校验（409 冲突→申请协同/转交）

系统公海/部门公海 ──[领取]D5 弹窗──→ 私海（可选立即激活）
审批中心 /approval/center ── 处理：转交/协同/手机号变更/报销
```

**数据流转主线**：录入联系人 → 激活业务关系（唯一锁定）→ 跟单/预约累积 → 档案补全 → 签约（业绩归属）→ 工单/台账/续约 → 续约或流失归档。

### 3.2 前置条件

| 页面 | 前置条件 |
|---|---|
| 全部业务页面 | 已登录（有效 token），否则跳 /login |
| 业务关系详情 | URL 携带 `id`；无数据权限显示 403 占位 |
| 高级搜索 | 部门经理 / 总经理；数据范围 = 当前用户**管辖部门列表** |
| 审批中心 | 所有人可见"我发起的"；"待我审批"仅经理+ |
| 公海规则/组织架构/系统设置 | 部门经理（本部门范围）/ 总经理（全公司） |
| 合同创建 | 业务关系存在 + 公司档案达"成交后强制"完善度 |
| 工作流阶段配置 | 经理+；按部门×产品线维度配置 |

### 3.3 后置条件

| 操作 | 完成后行为 |
|---|---|
| 写跟进成功 | 关闭弹窗；工作台"今日跟单记录"时间轴即时插入新记录；业务关系"下次跟进时间"同步刷新 |
| 新增预约成功 | 出现在工作台"今日新建预约"与预约管理对应 Tab |
| 外出登记成功 | 登记期间写的跟单记录自动关联并带 🚗 标记 |
| 录入成功 | 提示成功，可继续：激活业务关系 / 查看档案 / 继续录入 |
| 领取公海成功 | 卡片从公海移除，出现在业务关系"跟进中"视图 |
| 创建合同成功 | 跳合同详情；业务关系状态自动变"客户"，出现在"已合作"视图 |
| 审批通过（转交/协同） | 双方站内通知；业务关系归属即时变更 |
| 掉公海触发（系统自动） | 站内推送销售；业务关系进入部门公海并带"公海待领"标记 |

### 3.4 权限控制说明（前端实现要点）

| 控制项 | 规则 |
|---|---|
| 菜单可见性 | 高级搜索/审批中心（待我审批）/组织架构/系统设置：经理+；行政仅台账与合同（只读）；交付/行政无工作台入口 |
| 数据范围 | 销售=本人私海+本部门公海+公司公海；经理=管辖部门（可能多个）；总经理=全公司。**高级搜索、报表、预约管理均按"管辖部门列表"过滤** |
| **跟单记录可见范围** | 本人跟进的关系=全文可写；**协同关系**（`collaborator`）=全文可共同写；**他人私海**（本部门同事/跨部门）=**不可见**（除非走协同审批）；**公司公海/部门公海**客户=仅"近 30 天跟进 N 次"概览；跨业务线=仅"近 N 天 M 次"概览。详情见需求总纲 V2.1 §2.2 |
| **公司详情** | 经理+/总经理=全版；销售/交付/客服=**简版抽屉**（公司档案 + 本部门本产品线关系；他部门联系人电话 `****{后4位}` + 可「申请解锁」） |
| 高级搜索默认行为 | 默认仅显示**第一个管辖部门**数据，通过部门筛选器切换/多选查看其他管辖部门——默认收敛，按需展开；后端强制范围过滤 |
| 按钮禁用 | 完善度不足时"创建合同"禁用 + hover 提示；已有归属的激活按钮变"申请协同/转交" |
| 字段脱敏 | 跨业务线/跨部门：合同金额 `***`；续约日期仅"还剩 X 月"；跟单记录按可见范围（见上）；工单仅"N 个进行中"；**联系人手机号**：归属本人/协同=全号，非归属=`****{后4位}`+申请解锁 |
| 操作拦截 | 前端权限指令 v-perm 拦截 + 后端二次校验；401 跳登录，403 占位页 |

### 4.1.1 全局框架规范（V2.4 新增）

**① 侧边栏子菜单可折叠**

### 4.3 全局交互标准：一层抽屉 + 悬浮卡片（V2.6 新增，七叔裁决）

**定位**：凡展示"公司 / 联系人 / 销售 / 业务关系"的地方，都可作为**可点卡片/标签**查看明细；但**抽屉只做一层**，避免层层跳转的迷失感。

**① 一层抽屉铁律**
- 列表/卡片上点**公司名** → 打开第 1 层抽屉（公司档案概览）。**仅此一层，永不叠第二层抽屉**。
- 抽屉内再点**某条业务线/业务关系** → **整页跳转**到 `/relation/detail/:id`（抽屉自动关闭）——因为该页含跟单/工作流/合同/工单多 Tab，整页跳远优于叠层。
- 抽屉内点**联系人 / 销售** → **悬浮卡**（见③），不离开当前上下文。

**② 公司抽屉内容（分权限）**
- 经理+/总经理：完整（三档完善度 + 各业务线明细 + 联系人全号 + 跟单聚合）。
- 销售/交付/客服（**简版**）：公司档案（身份/制度/决策链/行业/地区/规模/业务线列表含签约日期，这些是全公司共享公共资产）+ 本部门本产品线关系；**非归属部门联系人手机号只显 `****{后4位}`** +「申请解锁」按钮（经理审批后限时可见全号，见 §3.4）。跟单聚合 Tab 对非本人关系只显"近 30 天 N 次"。

**③ 悬浮卡（第二层人的轻预览，桌面端）**
- **联系人悬浮卡**：姓名、职位、公司、手机号（按权限脱敏）、谈判特质标签（≤3，价格敏感/关系型…）、决策角色。卡片内"查看联系人详情"→ 整页跳 `/contact/detail/:id`。
- **销售悬浮卡**：姓名、头像、所属部门、负责产品线、联系方式（仅内联，方便约协同/转介绍）。**不放业绩数字、不放名下客户数**——业绩只在报表给经理+看，销售互查不暴露。销售卡到此为止，无下层跳转。
- 触发：桌面 **hover 显示 + click 钉住**（移开消失、点击固定）；组件规格（`.person-chip mini` + 浮层）见《设计规范 V3.0》三、四节。

**④ 移动端（H5）特例**
- 无 hover；轻点联系人/销售 → 底部弹**轻面板 sheet**（内容同悬浮卡），点遮罩关闭；**仍盖在当前抽屉/页面上，不叠第二层**。

**⑤ 跟单记录卡片（新增字段）**
- 每条跟单记录统一显示**谁填的**（填单人姓名+头像）+ **跟进的联系人**（联系人姓名，点开可看其悬浮卡）。数据来自接口出参 `createdByName` / `contactName`（见《接口 V1.4》C02/B05）。

### 页面 21：客户台账 /delivery/ledger

**基础信息**：title `客户台账`；按产品线分 Tab（网站建设/短视频推广/GEO 优化/财税/招牌网/房产网/法律咨询）。

**字段机制（V2.1 定案：字段模板驱动；V2.2 补强：存储与登记铁律）**：
- **通用字段（固定，所有产品线必有，不可删改）**：客户名称 ｜ 客户等级（A/B/C/D）｜ 签约时间 ｜ 到期时间（30 天内黄色预警）｜ 联系人 ｜ 交付对接人 ｜ 销售对接人 ｜ 备注
- **扩展字段（自由添加）**：每条产品线的差异化字段由**产品线管理页配置字段模板**（见页面 24），字段数据以 **JSON 存储**于台账记录的 `extraFields` 中；前端按字段模板动态渲染列与编辑表单
- 扩展字段控件类型支持：文本 / 数字 / 日期 / 单选 / 多选 / 链接；字段属性：标签、key、类型、是否必填、排序、是否列表显示
- 初始内置模板参考（可在产品线管理中修改）：网站建设（域名/域名到期/服务器/服务器到期/软件版本）；短视频推广（发布平台/账号数量/已发布视频数/曝光量/询盘量）；GEO 优化（已发布文章数/总收录词汇量/AI 推荐率/目标关键词）；财税（服务周期/当前账期）

**存储与登记铁律（前后端共同遵守，V2.2 新增）**：
1. **主表不动态新增物理列**——扩展字段值统一存 `extraFields` JSON 字段
2. **先登记、后写入**——所有自定义字段必须先在元数据表（字段模板）登记，**禁止无规则往 JSON 内丢 Key**；前端表单仅渲染模板中已登记字段，提交时剔除模板外 Key；`/ledger/save` 对未登记 Key 拒收（422）并告警
3. **Key 与类型不可变**——字段保存后 key 和控件类型不可修改；要调整只能"停用旧字段 + 新增字段"，防止历史数据失真
4. **停用不删除**——字段仅可停用（新记录不再出现该字段），历史记录中的旧值正常展示（灰色 + "已停用"标记），数据永不丢失

**渲染规则**：Tab 切换产品线 → 拉取该产品线字段模板 → 通用列 + 模板中"列表显示"的扩展列动态拼接表头；扩展字段值缺失显示 `-`。

**权限**：销售/客服/交付=自己负责的客户；经理=管辖部门；总经理=全部；行政=只读全量。到期时间可排序；行点击开台账详情抽屉（编辑权限按角色；编辑表单同样按字段模板动态渲染，保存时扩展字段整体写入 JSON）。

**数据来源说明（V2.3 明确）**：台账记录**由合同签约/服务开通时由服务端自动生成**，前端**不提供手工新增入口**；`K02` 仅用于编辑（传 `id`）。

**接口调用**：

| 操作 | 接口 | 关键字段 |

| 列表 + 字段模板（切 Tab 时） | `K01 GET /ledger/list` | 入参 `productLineId*`；出参 `{list,total,page,pageSize,fieldTemplate}` |
| 行点击抽屉 → 保存 | `K02 POST /ledger/save` | `extraFields` 含未登记 Key → `422 + 30101 + illegalKeys[]` |
| 排序（到期时间） | `K01` 的 `sort` | `expire_date:asc|desc` |
| —— 字段模板编辑器（页面 24 产品线管理）—— | | |

### 5.6 客户跟进与标签体系（V2.5 定稿 · 七轮讨论定案）

**核心原则**：
1. **标签跟着判断主体走**——判断属于谁，标签就挂谁身上：公司背景挂公司档案、人的谈判风格挂联系人、业务线判断挂业务关系。禁止把"人的特质"打在"公司"上误导全公司。
2. **系统能推导的不设标签**：进度由跟单动作建议、等级由回款自动算、风险由规则自动打——标签只留给"系统算不出、销售脑子里有"的信息。
3. **可统计的用字段、可浏览的用标签**。

#### 5.6.1 三层标签/字段总表

| 层级 | 内容 | 值域 | 维护方式 |
|---|---|---|---|
| **公司档案** | 身份标签（多选） | 本地知名 / 上市公司 / 国资背景 / 连锁集团 / 集团型 / 其他（可自定义增删） | **建档时人工勾一次**，全公司共享 |
| 公司档案 | 制度标签（多选） | 需招投标 / 已用竞品 / 集团统一采购… | 建档勾选，可后补 |
| 公司档案 | 决策链标签（单选） | 决策链短（老板直拍）/ 决策链长（多层评审）/ 未知 | 建档选一次；个别业务线差异在关系备注补充 |
| **联系人档案** | 谈判特质（结构化多选，≤3） | 价格敏感 / 关系型 / 方案型（要案例）/ 专业控 / …（可自定义增删） | 联系人详情手动，**跟着人走、换公司保留** |
| 联系人档案 | 决策权角色（已有字段） | 决策人 / 影响人 / 执行人 | 已有 |
| 联系人档案 | 个人标签（保留） | 自由 tag（爱喝茶/老板亲戚…） | 已有，与谈判特质并存 |
| **业务关系** | 业务线价值（单选·默认空） | 高 / 中 / 低 / 待定 | 销售手动，愿意标才标 |
| 业务关系 | 紧迫档（单选·默认灰度） | 周重点 / 月重点 / 季度跟 / 长期跟 / 灰度 | 纯销售手动 |
| 业务关系 | 客户等级 | A/B/C/D | **系统按回款自动算**（档位阈值=部门经理配置），不可手填 |
| 业务关系 | 风险标签（多选·自动为主） | 流失信号 / 回款风险 / 交付风险 / 对接人变动 | 系统规则自动打 + 人工可补 |
| 业务关系 | 协同标签（多选） | 需陪访 / 需技术支持 / 需方案支持 | 手动，可 @ 同事 |

**所有打标/改动留痕**（谁在何时打的），公司/联系人级标签全部门可见；业务关系级标签仅数据范围内可见。

#### 5.6.2 进度阶段（业务关系，6 步状态机）

| 阶段 | 验证动作 | 系统建议信号（跟单时自动建议） |
|---|---|---|
| 1 初步建联 | 首次有效电话/微信沟通 | 有通话/微信类跟单记录 |
| 2 需求确认 | 聊清预算/需求/决策链 | 有需求类记录 |
| 3 面访产品讲解 | 当面演示过产品 | 有外出/见面类记录（含移动端外出登记） |
| 4 异议与卡点 | 客户提出效果/价格疑虑 | 有异议类记录 |
| 5 逼单 | 明确报价、要求表态 | 手动进逼单（常与"周重点"呼应） |
| 6 已合作 | 签约回款 | 合同创建自动置位 |

- **动作驱动**：写跟单时弹窗右下角建议"当前动作 → 阶段 N"，销售确认或改，不必专门填阶段（**未见面≈停留在建联/需求确认磨；见过面犹豫≈异议与卡点**——卡点不再单独打标签）
- **允许跳级与回退**（如转介绍客户建联后直进逼单；异议没谈拢退回需求确认），**全部留痕记录操作人与时间**
- **异议无解两种出路**（系统建议、人工确认）：① 回落"长期跟"（等时机，不算死）② 判流失（写原因）
- 阶段到"已合作" → 业务关系状态自动转"客户"，进入合同/交付衔接

#### 5.6.3 紧迫档与灰度（业务关系）

| 紧迫档 | 语义（销售语言） | 颜色/样式 |
|---|---|---|
| 周重点 | 本周判生死——标记即承诺本周推进或放弃 | 红（实心） |
| 月重点 | 本月能往前推进 | 橙 |
| 季度跟 | 季度内推进 | 蓝 |
| 长期跟 | 值得长期维护（契合/决策顺），时机未到 | 绿 |
| 灰度（默认） | 暂未下结论 | 灰 |

- **手动标签，无自动复盘机制**（按七叔裁决，仅手动）
- **灰度寿命规则 = 部门级**：各部门经理在部门管理里配置"灰度 N 天未定性 → 系统提醒销售该下结论；再 M 天未动 → 列为公海释放候选，经理确认后释放"

#### 5.6.4 客户价值与客户等级（两轴分离）

| | 客户价值（开发价值） | 客户等级（贡献分级） |
|---|---|---|
| 回答 | 这条业务线值不值得投 | 现在给多少业务 |
| 值域 | 高/中/低/待定（默认空） | A/B/C/D |
| 维护 | 销售手动（愿意标才标） | **系统自动**按近 12 个月回款 |
| 归属 | 业务关系（契合度因线而异） | 业务关系（随签约回款变动） |
| 配置 | — | 金额档位阈值=**各部门经理在部门管理自配** |

> 两个反例约束：能长期跟的不一定最有实力（小公司但决策快）；有实力的不一定适合本条线（不契合则无价值）。因此价值判断以"该线契合度"为主，公司实力只作背景参考（见公司身份标签）。

#### 5.6.5 自动标签规则（风险预警，系统执行）

| 规则 | 触发条件 | 摘除条件 |

### 8.5 异常返回码处理

| code | 前端处理 |
|---|---|
| 401 | 清 token 跳 /login，"登录已过期" |
| 403 | /403 占位页或按钮级"无权限" |
| 404 | /404 占位页 |
| 409 | 业务弹窗展示冲突详情（归属人/版本戳），不跳页 |
| 410 | "该客户已入公海，请重新领取" |
| 422 | 字段级红字，定位首个错误 |
| 429 | "操作过于频繁，请稍后" |
| 500 | Message+重试；连续失败跳 /500 |
| 超时 >10s | "网络较慢请重试"，表单数据保留 |
| 业务子码 20101 | 手机号已存在 → 弹 D10 |
| 20102 | 公司相似候选 → 弹 D9 |
| **20103** | 统一社会信用代码已存在 → 字段级红字 |
| **20104** | 联系人有关联业务/合同不可删除 → MessageBox 显示 `refCount` |
| 20201 | 关系已被他人激活 → 弹 D6 冲突态，展示归属人 |
| 20202 | 完善度不足 → 跳补全页，展示 `missingFields[]` |
| 20301 | 客户已掉公海 → "请重新领取" |
| **30101** | 台账含未登记 Key → 提示 `illegalKeys[]`，表单保留 |
| **30201** | 字段被引用不可删 → 提示 `refCount`，仅可停用 |

## 十、异常 & 边界场景处理

1. **接口异常**：401/403/404/409/410/422/500 处理见 8.5；统一错误提示组件。
2. **网络超时**：>10s 提示+重试，表单数据保留。
3. **空数据**：所有列表/时间轴/图表/审批/搜索结果均有插画+引导文案（各页已定义）。
4. **超长文本**：公司全称表格列 >20 字截断+Tooltip；跟单摘要 >3 行折叠"展开全部"；标签 >3 个显示"+N"。
5. **数字/时间**：金额 ¥千分位两位小数；报表区可用"X.X 万"；时间 `YYYY-MM-DD HH:mm`，今天显示"今天 HH:mm"；剩余 <24h 显示"X 小时"；过期显示"已过期 X 天"。
6. **重复提交**：按钮 loading 禁用；写跟进/创建合同/新增预约携带幂等 uuid。
7. **并发冲突**：编辑页提交带 `updatedAt` 版本戳，409 提示"数据已被他人修改，请刷新"。
8. **激活竞态**：后到者收 409，弹窗展示归属人+申请协同/转交。
9. **掉公海瞬间操作**：写跟进返回 410，提示重新领取。
10. **预约边界**：过期预约保留 30 天归档；改期不创建新记录而是更新时间并留改期日志；完成预约强制关联跟单记录。
11. **审批边界**：申请人离职时其待审批单自动转交其直属经理；审批人不可审批本人申请（前端隐藏按钮+后端拦截）。
12. **附件**：≤20MB×5，PDF/图片/录音；超限前端拦截；上传中可取消。

## 十三、非功能需求

1. **性能**：首屏 ≤2s（4G，JS gzip ≤500KB）；列表 20 条渲染 ≤300ms；路由懒加载；跟单长时间轴滚动分页。
2. **安全**：手机号列表默认中间 4 位脱敏（详情按权限全量）；跨业务线按 3.4 脱敏；富文本 XSS 白名单；合同页水印；高级搜索后端强制按管辖部门过滤（前端筛选器只是体验层）。
3. **可测试要点**：
   - 权限矩阵 × 页面/按钮全遍历（内置 6 角色 × 管理岗组合）
   - 高级搜索：经理/跨部门经理/总经理三种范围 + 默认单部门行为
   - 台账字段模板：新增/停用扩展字段后，台账列与编辑表单动态变化、JSON 数据向后兼容（旧记录缺字段显示 `-`）
   - 移动端工作台：iOS/Android 微信内置浏览器完成 4 个快捷动作全流程
   - 预约四 Tab 口径（尤其"未预约"与掉公海倒计时一致性）
   - 完成预约强制留跟单记录闭环
   - 审批流：转交/协同/手机号变更/报销四条链路 + 自审拦截 + 离职转单
   - 激活 409 并发、完善度阻断签约、脱敏渲染截图比对
   - 台账字段治理：未登记 Key 提交被 422 拦截；字段停用后历史记录旧值正常展示（置灰+标记）；key/类型修改入口不存在
   - 掉公海 24h/6h 预警、空态/超长/大数字边界
