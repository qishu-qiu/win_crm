## 二、一致性问题清单（按严重度排序）

### 🔴 C1【严重】技术栈正面冲突（需求 vs 已定案 README）
- **需求 V2.0 §10.1**：后端 = "Java Spring Boot / Python Django"
- **README §一（2026-09-05 定案）**：后端 = **NestJS 12 + MySQL 8 + Redis**（路线 B2）；前端 = Vue3 + Vite + TS
- **技术栈方案对比.md**：结论停在"B1 Laravel 或 B2 NestJS 二选一"，**未记录"已选 NestJS"这一最终决策**
- **事实**：`backend/` 目录已是 NestJS 骨架（README §五确认可编译+单测通过）
- **风险**：需求文档会让后人/AI 误以为要 Java/Django，与现有代码和定案直接矛盾
- **建议**：需求 §10.1 改为 NestJS 12；技术栈文档补一节"已定案：NestJS（B2）"

### 🔴 C2【严重】工作流阶段：5 步 vs 6 步
- **需求 V2.0 §6.5.2**：初步接触 → 需求确认 → 方案报价 → 商务谈判 → 成交签约（5 步，命名不同）
- **DB V1.1 §8.4 / 接口 V1.3 §8.4 / 前端 V2.5 §5.6.2**：6 步 初建建联 → 需求确认 → 面访产品讲解 → 异议与卡点 → 逼单 → 已合作（七轮定稿）
- **矛盾点**：按接口文档自述的优先级（业务规则 V2.0 > 接口 > 前端 > DB），下游三份反而"错"了；但实际应以 6 步为准（已多轮定稿）
- **建议**：需求 §6.5.2 重写为 6 步，或加附录确认 6 步为最终标准

### 🔴 C3【严重】需求 V2.0 缺失整套"意向跟进体系"
以下在 DB V1.1 / 接口 V1.3 / 前端 V2.5 均已落地，但需求 V2.0 完全没有：
- 紧迫档 5 档（周重点/月重点/季度跟/长期跟/灰度）
- 业务线价值（高/中/低/待定，手动）
- 灰度寿命 + 部门规则（N12 / dept_rule，部门经理级配置）
- 公司画像标签（company_profile_tag：身份/制度/决策链）
- 联系人谈判特质（contact_trait，跟着人走）
- 关系网联系人（E08）、删除联系人（G08）、维护人变更（I05）、跟进设置（D18）、风险自动标签（O16）
- **风险**：权威总纲滞后，新同事/AI 以需求文档为准时会漏掉整套跟进体系
- **建议**：需求补「意向跟进体系」章节，对齐 V2.5

### 🟠 C4【高】台账扩展字段存储模型冲突
- **需求 V2.0 §7.3**：`t_product_fields` + `t_customer_product_data`（独立表存储差异化字段）
- **数据库 V1.1**：`field_template`（元数据表）+ `ledger.extra_fields`（**JSON 列**）
- **注**：需求 §4.7 其实已写"JSON 存储、key/类型不可变"——与 DB 一致；但 §7.3 的**表名/结构残留旧方案**
- **风险**：建表时物理方案直接二选一混乱
- **建议**：以 DB V1.1 的 JSON 方案为准，统一表名为 `field_template` + `ledger`

### 🟠 C5【高】核心表清单不一致（命名 / 数量）
- 需求 §7.2 列 **27 表**：含 `t_business_relation_status_log`、`t_product_fields`、`t_customer_product_data`、`t_reimbursement`、`t_data_import_task`、`t_form_submission`
- 数据库 V1.1 实际约 **33 表**：用 `relation_stage_log`（阶段推进留痕，语义不同于状态日志）、`field_template`+`ledger`（无独立 product_fields 表）、报销并入 `approval.payload`（是否独立表 §11 仍"待确认"）、**无独立 import/form 表**
- README §四 称"数据库设计文档 **26 表**"
- **数量 27 / 33 / 26 三份都对不上**
- **建议**：以 DB V1.1 为唯一真相（README 已认定），需求 §7.2 改为"引用数据库设计文档表清单"，不再另列冲突表名

### 🟡 C6【中】客户等级 vs 业务线价值 两轴分离未体现
- DB / 前端已明确：A/B/C/D（系统按回款自动算）≠ 高/中/低/待定（手动业务线价值）
- 需求 §5.1 业务关系字段表未体现两者分离
- **建议**：需求补两轴定义（与你的"回款贡献 / 开发价值"双轴裁决一致）

### 🟡 C7【中】SLA 报表范围漂移
- 需求 §九 MVP 明确"不做 SLA 报表"
- 但 DB 已建 `workorder.sla_deadline`、接口有 M05、前端有 SLA 报表 Tab
- **建议**：明确 SLA 属 V1 还是 V2，统一口径

### 🟢 C8【低】异步队列技术细节
- 需求 §10.1 提 RabbitMQ / Redis Stream；README / DB 只提 Redis
