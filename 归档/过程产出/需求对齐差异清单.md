## 六、核心亮点（值得复用的正确实现）

### 服务端架构纪律（可当标杆）

1. **横切层零 Prisma 原生**：DataScopeInterceptor / DesensitizeInterceptor / IdempotencyInterceptor 都是纯逻辑层，不 import Prisma —— 符合架构 §7.1 硬约束
2. **快速标记三层闸**：`quickMark` 方法自身不调 touchLastEventAt + `isEffectiveCommunication` 排除三型 + 常量定义 —— 三层隔离，防刷倒计时机制完备
3. **drop_in_x_days 单算法复用**：列表派生与掉海扫描逐字同算法（`resolveDropDeadline` + `countDaysUntilDrop`），按 Asia/Shanghai 自然日 —— 同一事实两个落点的坑已防住
4. **公海规则七步闭环**：canManageSeaRule → resolveEffectiveFrom → resolveSeaRuleFor → listManagerTodo → countAffectedCustomers → confirmed 两段式 → replaceRuleVersion —— 7 天缓冲完整实现
5. **幂等契约逐条合规**：SHA-256 body、模板路由取 path、超 64→400 不静默截断、同 key 异入参→409、业务成功后才落库

### 前端质量（可当标杆）

6. **角色矩阵唯一真相源**：`access.ts` 定义 → 路由守卫 / 侧栏 / 页面全部消费 —— 无散落的 `if (role === 'admin')`
7. **API 层完整覆盖**：`api/*.ts` 10 文件全部从 OpenAPI 生成物取类型 —— 零手写 DTO
8. **刷新令牌并发挂起队列**：isRefreshing + waitQueue 正确处理多并发 401 —— 虽有 timeout 风险，设计方向正确
9. **零 console 残留**：全 `src/` grep 零匹配
10. **废止口径零残留**：Grep 扫描覆盖 18 条废止登记号关键词

---

**审计结论**：整改后复审。核心横切层与已实现业务域的契约合规性优秀，主要差距集中在**未起子域的端点/页面缺失**而非已实现端点与契约的错位。建议以"联系人域 → 审批中心 → 阶段推进/转交 → 合同回款/分配 → 前端核心动线"为优先级链推进，其余子域按节奏排队。
