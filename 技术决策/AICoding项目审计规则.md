# AICoding项目审计规则 v1.0
> 适用对象：AI生成业务代码、AI Bug修复变更、AI自动产出测试用例
> 审计目标：防御LLM需求幻觉、补丁式绷带修复、测试用例自我欺骗假绿、隐性业务缺陷
> 风险分级定义
> - 极高危：阻断合并，必须重新设计实现，不可简单微调
> - 高危：必须修复并补充对应测试用例，修复完成人工复核
> - 中危：评估影响范围，可登记技术债务工单，限期整改，不可直接忽略
>
> 审计触发规则：所有AI产出代码/AI生成测试用例**强制全量审计**；人工编写代码按需抽样审计

## 模块1｜需求对齐审计（源头幻觉）
| 编号 | 审计项 | 违规判定 | 风险等级 |
| ---- | ---- | ---- | ---- |
| REQ-001 | 业务逻辑对齐原始需求，禁止以代码实现反推业务规则 | AI实现逻辑与原始需求不一致；AI私自删减需求例外规则、边界约束；脑补业务前置假设且无注释说明 | 极高危 |
| REQ-002 | 业务名词口径统一，变量/字段含义与业务文档保持一致 | 同一业务名词存在多套计算口径；变量命名符合业务名词，但内部计算偷换概念 | 极高危 |
| REQ-003 | 需求变更需检索全项目联动依赖，不可仅局部修改 | 仅修改当前函数，漏改关联枚举、常量、数据库映射、下游接口、配置项；无回归风险评估 | 中危 |

## 模块2｜代码实现审计（代码隐性缺陷）
| 编号 | 审计项 | 违规判定 | 风险等级 |
| ---- | ---- | ---- | ---- |
| CODE-001 | 资源显式释放，杜绝句柄/连接泄漏 | 文件、DB连接、Redis连接、httpClient、协程、流对象未做close/release；缺少finally/with自动释放机制 | 高危 |
| CODE-002 | 并发场景评估竞态、幂等；先查后更新需加锁/乐观锁 | 查询后更新无锁；重复请求会重复创建、重复扣款、重复下发消息；缺少幂等控制 | 高危 |
| CODE-003 | 异常捕获粒度合理，禁止大try-catch吞异常、丢失原始堆栈 | 超大范围try catch捕获全部异常，静默返回成功；丢弃原始exception堆栈；不打印业务入参、不返回标准业务错误码 | 高危 |
| CODE-004 | SQL禁止N+1查询、全表扫描，需评估索引有效性 | 循环内部执行数据库查询；无索引大表查询；一次性加载全表数据至内存；AI生成SQL未校验执行计划 | 高危 |
| CODE-005 | 禁止硬编码密钥、环境地址、业务阈值，统一抽配置/常量 | 密钥、域名、业务阈值写死在业务代码；未区分开发/测试/生产环境配置 | 高危 |
| CODE-006 | 时间统一使用UTC，业务逻辑不能依赖服务器本地时区 | 直接读取本地时间、硬编码固定时间；未处理毫秒、跨时区、夏令时场景 | 中危 |
| CODE-007 | 外部依赖版本兼容现有项目，不随意新增依赖包 | 引入项目不存在的包版本；新增无关依赖扩大安全攻击面；未校验package/requirements冲突 | 中危 |
| CODE-008 | 事务边界正确，保障原子性，避免半提交数据 | 事务提交/回滚时机错误；部分更新逻辑不在事务内，造成跨表数据不一致 | 高危 |
| CODE-009 | 参数校验后端强制校验，不可仅依赖前端校验 | 入参未校验：超大值、空值、特殊字符、非法类型直接透传到底层业务逻辑 | 高危 |
| CODE-010 | 缓存读写配套更新，防止脏缓存 | 更新数据库后不更新/删除缓存；缓存过期策略缺失，长期读取脏缓存 | 中危 |
| CODE-011 | 日志规范，禁止打印敏感信息，保留traceId与关键入参 | 缺少traceId；错误日志仅打印静态文字，不带入参；日志输出手机号、身份证、密钥等敏感数据 | 中危 |
| CODE-012 | 高可用保护：核心链路具备限流、熔断、降级设计 | 核心接口无流量保护逻辑，未评估流量突增雪崩风险 | 中危 |

## 模块3｜测试用例审计（核心：防御AI自我欺骗、假绿）
| 编号 | 审计项 | 违规判定 | 风险等级 |
| ---- | ---- | ---- | ---- |
| TEST-001 | 测试预期来自**原始需求**，禁止从被测代码运行结果推导断言 | AI读取业务代码，自动推断预期值编写断言；代码逻辑错误，用例预期同步错误，形成闭环假绿 | 极高危 |
| TEST-002 | 断言校验业务结果，禁止仅校验200/非空这类弱断言 | 仅校验http状态码、`is not null`，不校验业务数值、数据状态、数据库副作用；只校验返回体，不校验DB/MQ/缓存变更 | 极高危 |
| TEST-003 | 测试数据隔离，用例前后清理环境，禁止依赖存量脏数据 | 用例依赖环境预先存在数据；用例共享静态/全局变量，存在执行顺序依赖；单条执行与批量执行结果不一致 | 高危 |
| TEST-004 | Mock不能过度替代核心下游依赖，区分单元mock与集成测试 | 全部下游外部接口、数据库全部mock；单元测试全绿，无法发现真实下游协议/超时问题；无配套集成测试 | 高危 |
| TEST-005 | 用例覆盖异常、边界、非法入参分支，不能只写快乐路径 | 仅覆盖正向正常场景；空值、null、超大值、负数、特殊字符、权限拒绝、限流分支无测试用例 | 高危 |
| TEST-006 | 覆盖率评估优先看**分支覆盖率**，不可只看行覆盖率 | 行覆盖率高，但大量if/else、异常分支未执行；死代码、注释代码计入行覆盖率，指标虚高 | 中危 |
| TEST-007 | 禁止恒成立断言、注释断言、skip标记隐藏用例 | `assert 1==1`占位断言；断言被注释；用例被skip标记，但报告仍然统计为通过 | 高危 |
| TEST-008 | 安全场景独立覆盖：越权、重放、注入类场景 | 自动化用例完全不覆盖权限越权、SQL注入、XSS、接口重放场景 | 高危 |
| TEST-009 | 异步测试必须await，异步异常必须抛至测试框架 | 异步任务没有await，主线程提前结束，异步代码异常不会被捕获，直接标记pass | 中危 |

## 模块4｜Bug修复 & 代码变更审计（防御补丁式绷带修复、代码臃肿）
| 编号 | 审计项 | 违规判定 | 风险等级 |
| ---- | ---- | ---- | ---- |
| FIX-001 | Bug修复输出根因分析，禁止仅在报错点增加兜底补丁 | 仅在报错位置增加if判空、try-catch、硬编码特殊值绕开报错；不修复问题源头；未评估底层根本原因 | 极高危 |
| FIX-002 | 修复完成清理废弃旧代码、冗余分支，禁止补丁堆叠 | 新增多层if嵌套、多层兜底，旧分支旧逻辑保留；补丁之间互相冲突，持续堆积技术债务 | 高危 |
| FIX-003 | 修复输出回归风险清单，评估存量业务影响 | AI修复A问题，引入旧场景回归bug；没有针对原有业务场景补充回归用例 | 高危 |
| FIX-004 | 接口变更保证契约兼容，不能随意删除/变更字段 | 修改接口入参、返回字段，不兼容旧调用方；无降级兼容方案；未通知下游依赖方 | 高危 |
| FIX-005 | 注释和代码同步，禁止AI脑补注释 | 注释描述逻辑和真实代码不一致；修改代码后注释未同步更新 | 中危 |
