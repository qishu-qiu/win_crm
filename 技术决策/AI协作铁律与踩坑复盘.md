## 三、通例（由上述坑提炼，适用于所有文档与协作）

- **"防 AI 误读"的自检，必须出现在 AI 真会读到的那一页**（表头 / 章节首行），**不能只写在章程** —— 因为 AI 读表时不会回头翻章程（2026-09-12 定）。
- **规则本体放"读者会直接打开的那份文件"里**，上级文档只留**指针与动作项**。
- **同一事实只允许一个权威落点**；非权威位置必须显式标注定位（如「索引·非规范」），否则会被 AI 当成规范。
- **"三绿"不等于"能跑"**：`tsc` / `lint` / `test` 全过只证明**编译期与测试期**成立。凡涉及**模块解析、依赖加载格式、打包产物**的改动，必须**真起一次进程**（`node dist/*.js`）才算验完 —— 坑 11 / 12 / 13 都是"三绿全过但跑不起来或产物不干净"（2026-09-14 定）。
- **否定式约束（"不许查库 / 不许越权 / 不许依赖某层"）要用「无法表达」来证，不要用「跑一遍没发生」来证**：前者是结构事实（依赖没注入 → 不可能调用），后者只覆盖一次执行、还容易被框架自身行为干扰（坑 15）（2026-09-14 定）。
- **判据与规格冲突时**：先比规格（上游优先），按规格做；**冲突本身必须写进报告**并在实现处注明依据，**不许静默按计划/顺手口径做**（坑 17）（2026-09-14 定）。
- **"命令没跑"不等于"命令通过"**：管道 / 子命令失败时，外层 `&&` 链会停在失败点，若失败段恰在最末，前面的 OK 极易被读成整体通过 —— 验收必须看到**该命令自己的结果输出**（如 jest 的 `Tests: N passed`），不看"到没报错"（坑 18）（2026-09-14 定）。
- **文档联动不是"额外动作"，是执行令的一部分**（→ §一 F）：凡改口径 / 接口 / 表结构，**同批**把上游文档、下游指针（README / CODEBUDDY.md / 代码注释里的版本号）、生成物（`gen:types`）一起改掉，**不另行请示**；只有"写新口径"才需要先拿指令（2026-09-14 定）。
- **批量改文件的验收与改代码同等严格**：`tsc / lint / test` 全绿**证明不了** md / 注释没被写坏（坑 19 实测）—— 批量文本改动必须配**"改动行数上限 + 损坏签名 grep + 试跑单文件"**这三板斧，且**首选定点工具（编辑器级替换），而非正则脚本**（2026-09-15 定）。
- **命令输出只让它走一路**（2026-09-15 实测）：`npm` / `jest` 的输出在 `stdout` 与 `stderr` **几乎逐字重复**，两头都读＝**白烧一倍上下文**（本窗口 4 次全量测试无一例外）。一律 `2>&1 | Select-Object -Last N` 并**只取一处**；能合并的校验命令**合并成一条**。★ 这属**读的纪律**，与"少读规则"是两回事 —— **该读的规则不省，重复的输出必须省**（→ `CODEBUDDY.md §11`）。
- **"清单"要先判是不是穷尽**（2026-09-15 立 · 当日通盘审计）：规格里的**括号列举 / 「如…」/「A、B、C」默认是举例**；只有写了「**完整清单**」「**一律**」，或需求 §十六 表头那种"表里没有才代表允许"才算**穷尽**。
  - **不许**由"清单外"推出「**不做**」（漏做：§7.4 敏感动作 → B/C 域"不写审计"）；
  - **也不许**推出「**可以做**」（放任：管理员"只读"举例 → 放行建档）。
  - ★ **两种误读方向相反、后果都是错**，且**都发生过**：本项目已翻车 **5 次**（+ 数据架构 A6 `perm_key`、接口 §2.6 `urgency` / `stage` 举例 →《废止口径登记表》#31 / #36 / #37）。读法铁律钉在**需求 §1.3**（读者会打开的那一页）。
