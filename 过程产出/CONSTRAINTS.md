## 二、不可协商的硬约束（任一违反＝直接打回）

1. **模块边界**：只依赖更低层；同层互禁；`domain/**` 不 import 框架 / Prisma；`*.repository.ts` 只被本域引用（架构 §5.2 / §5.4）。
2. **数据范围只在拦截器注入**，`repository` **不得手写** `where owner_id = ...`（架构 §七）。
3. **脱敏只在出口**；**报表 / 看板 / 汇总出口不脱敏**（需求 §4.3 / 架构 §七）。
4. **审计留痕**（架构 §7.4）：**所有增删改**由**统一审计切面**写 `operation_log`（需求 §4.2 ★「全量留痕 · 符合等保」）；**敏感动作**须在**业务事务内**写、业务回滚审计一起回滚；**查看类**（管理员每次查看）为**独立写入**、best-effort、**不阻断读**。
5. **跨域只走 service / 领域事件**，**禁止跨域大事务**；多表改只在本域 `$transaction`（架构 §5.3）。
6. **Worker 全局只 1 实例**（架构 §六）。
7. 负向功能一律以需求 **§十六《否决与后置清单》**为准：**"表里没有"才代表"允许"**。
8. 业务规则变更 → 受影响的接口 / 前端 / 数据架构**同批升级、同一次 git 提交**（README §八 L0 铁律）。
9. 枚举一律 `String` 英文码，**不用 DB ENUM**；展示文案走 `dict_item`（数据架构 §15.5）。
10. 唯一冲突按 **P2002**（不是 MySQL 1062）→ 409 撞单/竞态、422 业务校验，约束名从 `meta.driverAdapterError.cause.constraint.index` 取（**非 `meta.target`** —— v7 实测，→ 废止口径 #29）出人话（架构 §七）。

## 三、"完成"的定义（DoD）

一个任务只有在**同时**满足以下四条时才算完成：

1. 代码合入 `main`，且 **T0 / T1 全绿**；
2. 有**可粘贴的证据**（命令 + 输出）；
3. 涉及业务铁律的，`domain/` 有**对应单测**；
4. 触动规则的，已按 **L0** 联动改文档（同一次提交）。

> 每个里程碑出口另需过 **T2**；发布前另需过 **T3**。
