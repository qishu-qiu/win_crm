### 片 1（核心）：录入页补成 3 步，并且**能激活业务关系**
口径＝《前端页面与交互文档》§5 第 7 条 ＋ 需求 §12.1。

- **3 步步骤条**：① 联系人 → ② 公司 → ③ 确认。
- **第 2 步「公司」可跳过**：选「暂不填公司，先存为待跟进」→ 只建联系人 ＝「待关联」。
  服务端**已就绪**：`POST /contacts` **不传 `company_id`** 即可，服务端自动写归属（`owner_id` ＝ 建档人）。
  ⚠ 跳过后**不要让用户选部门 / 产品线** —— 部门 × 产品线是**业务关系**的属性，没有公司就没有关系（需求 §6.1 ⑧）。
- **第 3 步「确认」＝ 激活业务关系**：
  - 端点 `POST /relations`，req `{company_id, dept_id, product_line_id}` → resp ＝ 关系列表项；撞 `uk_active_rel` → **409 / 20401**（把那句服务端人话直接显示）。
  - **产品线下拉** 用**新端点** `GET /org/product-lines`（回 `{id,name,code,color_key,dept_ids,service_cycle_days,status}`）；
    `color_key` **可能为 null** → 前端自行回落，**不许编默认色**。
  - **部门下拉** 用已有的 `GET /org/departments`。
  - 建完关系后：提示成功 ＋ 给一条通往关系详情的路径（`/relations/:id`）。
- **撞库 4 分支**（需求 §12.1）：
  - ✅ 本片做：**分支 3**（跨部门可并行：只显对方部门名＋日期，**不露跟单内容**）、**分支 4**（挂现有公司 / 确认新建，**疑似重复必须留"强行新建"出口**，强行新建要留痕）。
  - ⛔ 本片**做不了**（**不摆假入口**，登记欠账）：**分支 1**（公海可直领 → 依赖 F 域认领）、**分支 2**（本部门已激活 → 申请转交 / 协同 → 依赖 G 域审批）。
- **验收**：真账号走一遍：建联系人 →（跳过或建公司）→ 激活关系 → 跳到关系详情；且**列表页能看到这条新关系**。

### 片 3：批量快速标记入口
- 端点**已就绪**：`POST /events/quick-mark`，req `{relation_ids?[],contact_ids?[],outcome}`（**两组至少一组非空**）。
  - `outcome` 三型：`not_contacted` / `no_answer` / `brief_hangup`（前端常量已有：`前端/src/engine.ts` 的 `QUICK_MARK_OUTCOME_OPTIONS`）。
  - 关系侧判**可写**（越权 / 只读 → 403）；`contact_ids` **只有归属人能标**（别人 → 403）。
  - **不重置掉海倒计时**（服务端保证），前端**不要**自己在界面写"已刷新跟进时间"之类的话。
- 前端要做：业务关系列表页**勾选多行** → 动作条「快速标记」三选一 → 调接口 → 提示「已标记 N 条」＋ 刷新列表。

## 二、动手前必须知道的 5 条口径（做错就返工）

1. **「待关联」＝ 没挂公司**：判定＝该联系人在 `company_contact` 里没有任何行（**派生，不加字段**）；它**不占部门、不占产品线**，不进业务关系列表、不掉海。
2. **待关联联系人的归属**＝建档人（`contact.owner_id`）；**归属可改**（经理分派 / 离职交接），**不走审批、只留痕** —— 这是口径，不是"以后再说"。
3. **快速标记**：不写幂等键（**每次点击都该是一条独立记录** —— "这个客户打过 N 次"就是这么统计的）、**不回写 `last_event_at`**、`action_type` 固定 `phone`。
4. **前端不许自己判业务规则**：能不能标、算不算重复、是不是有效跟进 —— 全看服务端返回值与人话（前端再判一遍＝第二套规则，迟早分叉）。
5. **`GET /contacts` 的可见范围是"服务端收敛"**：前端不要为了"看到更多"绕过（比如自己拼参数）。
