## 四、本窗口修掉的 3 处缺陷（**都是 M0 遗留**，下个窗口别再信 M0 的旧结论）

1. **`AuditService` 根本没有装配点** —— M0-30 只落了 `audit.service.ts`，没落 module，谁都注入不了。已新增 `src/kernel/audit/audit.module.ts`（`@Global`）并接入 `app.module.ts`。
2. **统一响应包漏了 bigint 收口** —— M0-33 只验了「四字段 ＋ void→null」，**没验 bigint**。主键是 `BigInt @db.UnsignedBigInt`，而 `JSON.stringify(1n)` **直接抛错** ⇒ 任何返回 id 的接口都会 500。已在 `response.interceptor.ts` **唯一收口处**补 `toJsonSafe`，并补 2 条用例（含「不转真会炸」的前置断言）。§2.3 表格里 `user.id="3"` 就是这条修复的现场证据。
3. **`mergePermissionLevels` 没用 `roleCodes` 过滤** —— 仓储万一多带一行就是**越权**且线上无提示。已改为「出参只可能由该员工自己的角色码决定」。

## 六、环境 / 操作踩坑（下个窗口别重踩）

1. **3000 端口当前无服务**（本窗口已按你的指令关掉其他后台 dev 进程：前端 vite 5173、后端 start:web 3000）。**请用 `PORT=3100` 起自己的实例**，避免多窗口抢端口。
   ```powershell
   cd 'd:/WorkBuddy/销售标准管理/服务端'; npm run build
   Start-Process -FilePath 'cmd.exe' -ArgumentList '/c set PORT=3100 && node dist/main.js' -WorkingDirectory 'd:/WorkBuddy/销售标准管理/服务端' -RedirectStandardOutput '...\.tmpboot.log' -RedirectStandardError '...\.tmpboot.err'
   ```
   起服后记得记下 PID 便于收工关掉。
2. **给 curl 送 JSON body 不要用 PowerShell 管道** —— 实测体没被解析，所有 POST 都返回过滤器兜底文案「请求参数有误」，差点被误判成「校验通过」。**改用文件送体**：`Out-File -Encoding ascii -NoNewline` 写文件 → `--data-binary "@文件"`。
3. `Get-Content` **必须带 `-Encoding`**（否则工具会拦截，编码风险）。
4. PowerShell 5.1 **不支持 `<` 输入重定向**；mysql 用 `-e "source ..."` 代替。
5. `source` 打不开中文路径 → 复制到 ASCII 临时路径再执行（见 §三）。
6. **`operation_log` 是分区表**，实测分区覆盖 `p202609~p202712 + pmax`，当前月份有分区，审计写入不会失败。⚠ 但 **2027-01 之后需要补分区**，否则审计写入会报「no partition」。
7. 真库 `updated_at` 是 `datetime NOT NULL` **且无默认值** → 裸 SQL 插入必须显式给值（Prisma 的 `@updatedAt` 只在 ORM 内生效）。
8. `employee_role.role_code` / `permission_matrix.role_code` 是**外键指向 `role.code`（不是 id）** → 角色必须先插入。
