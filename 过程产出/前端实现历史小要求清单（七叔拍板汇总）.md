# 前端实现 · 历史小要求清单（七叔拍板汇总）

> 用途：把七叔在 2026-09-04 ~ 09-10 期间对**前端呈现与实现**提过的所有「看起来是细节、但决定好不好用」的要求，一次性捞回、归类、锁定。
> 这是写《销售CRM前端页面与交互文档》V1.0 的**硬输入**——每条新页面/组件都必须能对上这里，对不上就停。
> 真相源优先级：业务需求文档 §13（全局交互规范）＞ 本清单 ＞ 设计规范 V3.0 ＞ 原型保留清单。
> 标注：`[铁律]` 不可违背；`[方向]` 2026-09-09 推翻重做定调，原型旧视觉不满足；`[约定]` 与接口/数据层对齐的硬约定。

| A4 | **销售悬浮卡只放基础信息**（姓名/头像/部门/负责产品线/联系方式），**不放业绩数字、不放名下客户数** | §13.1 / 2026-09-08 |
| A5 | 联系人悬浮卡：姓名/职位/公司/手机号（按权限脱敏）/谈判特质（≤3）/决策角色；「查看联系人详情」整页跳 | §13.1 |
| A6 | **跟单记录卡片统一显示「填单人 + 跟进联系人」**，两个都可点看悬浮卡 | §13.1 / 设计规范 V3.0 §七 |
| A7 | 移动端无 hover → 轻面板 `.sheet`（点遮罩关闭），仍盖当前页/抽屉上，**不叠新抽屉** | §13.1 / 设计规范 §七.6 |

## D. 框架组件小要求（设计规范 V3.0）

| # | 要求 | 来源 |
|---|---|---|
| D1 | 侧栏子菜单**可折叠**：默认仅展开当前分组；折叠状态按账号持久化（localStorage） | 设计规范 §一 |
| D2 | 顶部居中快捷入口（胶囊，≤6 项）：**只放动作型**（写跟进/新增预约/外出登记/录入客户/公海领取…）；数据看板类不进（仅工作台承载） | 设计规范 §二 / §13.4 |
| D3 | 快捷入口默认值由**角色模板下发**：销售默认 4 个（写跟进/新增预约/外出登记/录入客户），经理追加「待我审批」 | §13.4 |
| D4 | 人员芯片：头像色 = **姓名哈希 12 色**（非角色色）、字取首字；可上传自定义头像；列表用 `.mini`、详情用完整三件套；未指派显「＋ 指派」 | 设计规范 §三 / §13.3 |
| D5 | 实体标签：产品线**全系统固定配色**（7 线各一色）；部门色在【部门管理】配置、未配回退蓝；员工灰底；「部门·产品线」拆两个标签 | 设计规范 §四 / §13.3 |
| D6 | 客户标签四维（注意力 focus / 打法特征 play / 风险 risk / 协同 coop）；系统自动打的加 `.auto`（⚙ 灰、不可手改） | 设计规范 §五 |
| D7 | 打标签入口**嵌在「写跟进」弹窗最后一步**，不单独设页面 | 设计规范 §五 / 保留清单 §三 |
| D8 | 跟单聚合：默认**近 1 个月**；以**当前登录人**为界，本人填的走**主线**、他人（协同/合并前）走**树杈**，两色分开不混；带图例 | 设计规范 §八 / 业务需求 §7.5 |
| D9 | 公司详情销售 = **简版**（档案共享 + 别部门手机号脱敏 + 跟单聚合对非本人关系只显「近 30 天 N 次」） | §13.2 |
