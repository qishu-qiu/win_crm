## 二、大厂是怎么做的（四条，都能对上我们已有的做法）

**① 组件分四层，职责逐层收窄**

| 层 | 是什么 | 例子 | 谁维护 |
| --- | --- | --- | --- |
| **基础组件** | 原子件，只负责"长得对、能交互" | Button / Input / Table（＝**Ant Design**，我们已引） | 组件库（不自己写） |
| **业务组件** | 基础件拼出来的**跨页复用**件，强业务特征、项目内频繁出现 | **联系人悬停卡**、金额展示（脱敏形态）、状态圆点 | 我们自己（`components/`） |
| **区块** | 业务组件拼成"页面的一块" | 查询条件 ＋ 表格 ＋ 翻页器 | 我们自己（`components/` 或页面内） |
| **模块 / 页面** | 整页组装 | 业务关系列表页 | 页面（`views/`） |

**② 抽取判据：重复 ≥ 2 次才抽**（两篇来源一致）
- 只出现 1 次 / 只有几行 / 拆完代码更多 → **不抽**（避免"为复用而过度抽象"）。
- 一旦某个业务件在多个页面反复出现 → **必须抽**，不许各页复制一份。

**③ 统一出口 ＋ 硬约束（字节的关键一条）**
- 字节的做法是：**强制所有业务组件从设计系统统一导出，不允许各团队自建组件**；且**靠 monorepo ＋ lint 检查做硬性约束**，不是靠口号。
- ★ **这一条与我们服务端的做法同源**：本项目已经用 ESLint `no-restricted-imports` 硬卡七域的依赖方向（架构 §5.4「靠工具，不靠自觉」）。**前端复用同理 —— 立了规矩就得有机械卡点，否则等于没立**。

**④ 单一职责 ＋ 取数与渲染分离**
- 组件只回答"长什么样"；**请求与渲染要拆开**（职责混杂会抬高复用成本）—— 对应我们：取数在 `api/`、展示口径在 `*.ts`、组件只管渲染。

## 三、对照本项目（现状 → 差距）

| 大厂做法 | 我们的现状 | 差距 |
| --- | --- | --- |
| 四层组件 | 只有 `views/`（页面）＋ `api/`（取数）＋ `*.ts`（展示口径）；**`components/` 是空目录** | **缺"业务组件"这一层** |
| 重复 ≥2 次必抽 | 无任何约定 | **无规矩** → 各页复制，改一处漏多处 |
| 统一出口 ＋ lint 硬卡 | 服务端已硬卡，前端**零卡点** | 前端无机械防线 |
| 页面 → 区块 → 组件 → 基础件 单向依赖 | 无约定 | 可能出现反向依赖 |

**结论**：**只要立规矩，答案就是"改一处"** —— 悬停卡放 `components/ContactHoverCard.vue`，工作台 / 关系列表 / 详情页都引它，改那一个文件即可。**不立规矩，它必然变成三份**（这正是服务端反复翻车的一号坑的前端版）。

## 四、建议怎么立（供拍板）

**① 补一节《架构设计说明》「前端目录与组件约定」**（架构说明现在只管服务端），核心三条：
1. **目录**：`views/`（页面）｜`components/`（跨页复用的业务组件与区块）｜`api/`（取数，类型一律来自 OpenAPI 生成物）｜`*.ts`（展示口径：中文名 / 颜色 / 格式）。
2. **依赖单向**：`views` → `components` → `api` / 基础组件（Ant Design）；**不许反向**，也不许 `components` 里直接连 `api`（由页面把数据喂进来，否则每个页面都得各配一次取数逻辑）。
3. **抽取判据（写死）**：**同一个东西第二次出现，就必须搬进 `components/`**；只出现一次的不许提前抽。

**② 加一条机械卡点**（与大厂③ 对齐，也与我们服务端的做法同源）：用 ESLint 把"`views/` 不许互相 import / `components/` 不许 import `views/`"这类**目录级方向**卡住 —— **靠工具，不靠自觉**。

**③ 修掉 `router/index.ts` 头注里那句错引**（它引的「架构说明 §四 目录树」不存在）。

**影响范围**：只加一节文档 ＋ 一条 lint 规则 ＋ 修一处错引；**不改库、不改接口、不动业务逻辑**。但它决定 **M6-08 及以后所有页面**怎么组织 —— 越早定越省。

## 五、不做什么（避免过度设计）

- **不引 monorepo**：本项目是单仓单前端（`前端/`），字节那套是为**千人团队 / 万级组件**设计的；我们照抄＝杀鸡用牛刀。
- **不发 npm 包**：跨**项目**复用才需要发包；我们只在**项目内**复用，目录里放一个组件即可。
- **不引 pinia 之前先别谈缓存**：组件间共享数据若要缓存，才需要引入状态库 —— **引依赖要单独拍板**（项目现仍用 `src/session.ts`）。
