# 前端补全至「可试用」开发计划（M8-06 候选）

> 方法论：生产级工程生命周期技能（Define→Plan）。薄切片、每片带验收与依赖、验证不可协商。
> 真相源：前端文档 §五（29 页）/ §四（信息架构）/ 设计规范；接口 §五；需求对应节。
> 联动铁律 L0：行为/页面一变 → 前端文档 + 接口 + 需求同批升版、同一次 git 提交。

## 0. Define · 目标与范围

- **目标**：把前端从「最小单测」补到「销售可真实试用」——补全**应用骨架 + 统一交互原件 + 7 张高频页**，并修掉试用反馈的 **A1 / A2 / A3** 三处真实缺陷。
- **不做（本计划外，后续里程碑）**：29 页里非高频的 22 页（合同 / 工单 / 台账 / 审批 / 报表 / 组织架构 / 系统设置 / 目标 / 消息中心 / 移动端）。
- **范围拍板点**（见 §6）：只做 7 高频页（＋壳＋修三缺陷），还是扩大到公司档案/联系人档案等？

## 1. 现状差距盘点

- **已实现（8 页）**：login / workbench / entry / relations / relation-detail / contacts / contact-detail / appearance。
- **目标（§五 29 页）**；高频 ★ 7 页＝数据看板 / 工作台 / 预约管理 / 业务关系列表 / 业务关系详情 / 录入 / 系统公海＋部门公海。
- **已知缺陷**（来自 M8-05 真人试用）：
  - **A1** 工作台空：`GET /today-agenda` 直查 `daily_agenda`（靠 M7 每日 05:00 组装），M7 未做 → 永远空。
  - **A2** 无「公司」模块前端页面（无列表/详情/新建）；`CreateContactDto.phone` 必填、无微信入口 → 只微信客户录不进。
  - **A3** 撞号后跳通用 `/contacts` 列表、无具体人直达（`search-dup` by phone 只回公司候选，无联系人 id）。
- **交互原件缺失**：侧栏菜单（§四固定顺序）、顶部栏（铃铛/头像/外观）、实体可点＋一层抽屉＋悬浮卡（A1~A7）、响应式窄屏。

## 2. Phase 0 · 后端就绪度核查（必须先行，否则后续片会卡）

- 对每张高频页列「所需端点」，对照 `服务端/src/modules/**/*.controller.ts` 已实现路由，产出**缺口表**。
- 重点关注（预计缺口）：看板 4 KPI / 目标进度（需求 §7.11）/ 僵尸榜 / 公海决策待办；预约 CRUD；公海领取；`today-agenda` 实时兜底。
- **退出标准**：7 页端点清单 + 缺口表；缺口要么进本计划补做、要么登记《欠账登记表》。

## 3. Plan · 分阶段（垂直薄切片，每片独立可验证）

### Phase 1 · 应用骨架与统一交互原件（所有页共用）
- 侧栏菜单（§四一级顺序，角色矩阵 `access.ts` 可见性）、顶部栏（铃铛角标/头像/外观入口）、路由骨架补全。
- 交互原件：`components/` 下「实体可点」「一层抽屉」「悬浮卡(.sheet 移动端)」三件套（A1~A7）。
- **验收**：导航可达全部已实现页；点公司/联系人/员工名称有跳转或抽屉；窄屏可读；`npm run lint` 过。

### Phase 2 · 工作台修复（A1）＋ 录入修复（A2/A3）
- **A1**：`todayAgenda()` 加实时兜底（当日 `daily_agenda` 无行时按活数据算逾期未跟进/今日到期承诺）；或先做 M7 组装任务（二选一，见 §6）。
- **A2a**：加「只建公司」入口（录入页增加"先建公司"模式或独立页，调 `POST /companies` 不带联系人）。
- **A2b**：后端 `CreateContactDto.phone` 改 `@IsOptional` + 前端加微信字段，校验「手机或微信至少其一」。
- **A3**：后端 `search-dup`（by phone）额外回命中联系人 `id+name`；前端撞号提示改为「查看 [姓名] 的档案」直达 `/contacts/:id`。
- **验收**：工作台有内容；可只建公司；只微信客户能录；撞号直达具体人。文档联动：接口 §5.4/§5.5、需求 §12.1/§5.5。

### Phase 3 · 业务关系列表 / 详情 体验打磨
- 列表：阶段彩点、逾期红、**到期当天掉公海⚠**（#41 按天）、紧迫档 5 档筛选与批量标记（仅私海）、分页、实体可点。
- 详情：8 Tab、跟单时间轴（按「归属轮次」分组）、写跟单、新增预约、判死/流失、同公司其他关系脱敏卡。
- **验收**：列表筛选/分页可用；详情各 Tab 可达；写跟单/预约/判死通。

### Phase 4 · 数据看板（★）
- 4 KPI + 今日待跟进（逾期红置顶，主按钮写跟进）+ 目标进度条（§7.11）+ 周重点僵尸榜 + 公海超期决策待办（经理）。
- 首屏分层：销售＝答"今天干什么"；经理/老板＝"需我决策"聚合卡。
- **验收**：销售首屏第一屏答今天干什么；经理首屏聚合待决策。依赖 Phase 0 看板端点。

### Phase 5 · 预约管理（★）
- 4 Tab（今日/未来/过期红 count/未预约）、距掉公海 X 天倒计时、完成预约强制生成跟单（否则 422）、批量。
- **验收**：4 Tab 切换；过期红；完成预约生成跟单。依赖 Phase 0 预约端点。

### Phase 6 · 系统公海 / 部门公海（★）
- 列表 + 领取（私海可领）、老客户徽标、入海历史、经理超期决策待办。
- **验收**：销售可领；经理可见超期决策。依赖 Phase 0 公海领取端点。

## 4. 质量门（CONSTRAINTS，验证不可协商）

- **前端**：`npm run build`（vue-tsc 类型检查 + 打包）零错误；`npm run lint` 过；`npm run dev`（5173）真机点一遍每页核心动线。
- **后端（涉及改动）**：`npx tsc --noEmit` / `npm run lint` / `npm test`（domain 单测）。
- **文档联动**：行为/页面变更同批升版（前端文档 §五/§六、接口 §五、需求对应节），进同一 git 提交；严禁 `git add -A`。
- **每 Phase 退出**：dev 真跑核心动线有证据（证据入《交接说明》），再进下一 Phase。

## 5. 依赖与风险

- 后端缺口（看板 KPI / 预约 / 公海领取 / today-agenda 兜底）可能阻塞 Phase 2/4/5/6 → **Phase 0 先清**。
- 文档联动成本高但为铁律 L0，漏联动＝版本沿革断档。
- 每 Phase 变更保持 ~100 行，大改动拆开评审（五轴审查）。
