## 一、客户模型三层映射（系统的地基，一个字都不能错）

> 摘自《项目摘要 V2》+ 需求 V2.1。这是整个 CRM 区别于传统"客户表多份"的灵魂。

- **第 1 层 公司公海 = 主实体池**：1 家公司 = 1 个档案，全网唯一共享，无论几个部门对接。
- **第 2 层 部门公海 + 员工私海**：部门主动认领的有价值客户。
- **第 3 层 业务关系 = 最小业务单元**：`公司 × 部门 × 产品线 × 对接人 × 销售`。
  - 一家公司可有**多条业务关系**（不同部门/不同产品线各自独立跟进），产品线界面必须体现。
- **对接人以手机号为唯一索引**：跳槽也保留历史 → 形成"客户关系网"（relation-detail 的"关系网"Tab）。
- **签单人与维护人分离**：离职不动业绩归属、换人不影响客户体验（合同页签单人🔒锁定、维护人可变更）。

**原型页面直接对应**：company/contact/relation 的 list + detail、录入向导、海。

## 二、业务关系"判定生死的客户打法"（意向跟进体系，七叔亲授）

> 2026-09-07 七叔亲授销售真实打法，V2.5 定稿。这是"业务逻辑最不能丢"的一块。

### 2.1 两个字段正交，绝不能混成一个
- **进度（阶段）= 客观事实**（客户现在到哪一步了）
- **紧迫（周重点…）= 主观计划**（我这个周期打算推不推）

### 2.2 真实 6 阶段（替换任何"5 步工作流"模板）
```
初步建联 → 需求确认 → 面访产品讲解 → 异议与卡点 → 逼单 → 已合作
```
- 动作驱动推进建议；**可跳级、可回退、全程留痕**。
- 异议无解 → 可回落"长期跟" 或 判流失，不能一直挂着。

### 2.3 紧迫档位（5 档，替代旧 focus 四值）
**周重点 / 月重点 / 季度跟 / 长期跟 / 灰度（默认）**
- 周重点 = 本周判生死的客户，本周不推进就放弃或升华。**标记即承诺本周动作**。
- 灰度 = 暂未下结论；**灰度的"保鲜寿命"= 部门经理级配置**（到期没动作系统提示）。
- 业务信条：**"不存在吊着我们的客户，吊着的都不是意向"**——真实意向只有两个卡点：
  **① 见不到人（卡在约见面）② 犹豫效果和价格（卡在异议处理）**。

### 2.4 客户等级 ≠ 客户价值（两个不同轴，原型别画成一个）
- **客户等级 = 回款贡献**：建议系统自动按金额档位算，档位由**各部门经理自配**。
- **客户价值 = 实力 × 契合度（开发价值）**：默认空、可手动标记。

## 三、标签体系：三层归属 + "系统能推导的不设标签"

> 标签跟着"判断主体"走，防标签通胀。这是七叔反复敲打的点。

| 归属层 | 挂什么标签 | 关键规则 |
| --- | --- | --- |
| ① **公司档案** | 身份标签（多选）/ 制度标签（多选）/ 决策链（单选） | 建档勾一次、全公司共享、打标人留痕。**全项目叫「公司档案」，禁用"公司画像"**。 |
| ② **联系人档案** | 谈判特质（≤3）：价格敏感/关系型/方案型… | 每人最多 3 个 |
| ③ **业务关系** | 紧迫档 / 业务线价值(高/中/低/空) / 风险 / 协同 | 紧迫见上；风险支持系统自动打（带⚙灰色标） |

**铁律**：
- **系统能推导的不设标签**；可统计的用字段、可浏览的用标签。
- 阶段/意向/等级这类**不要重复打标签**（旧设计曾想加，已否决）。
- 打法特征标签标"谁打的"留痕可查。
- 打标签入口：**嵌在"写跟进"弹窗最后一步**，不单独设页面。

## 四、跟单可见性 + 全局抽屉（2026-09-08 七叔最终裁决，最容易做错的一块）

### 4.1 跟单记录可见范围分档（不是一刀切"可见/不可见"）
| 对象 | 我能看到 |
| --- | --- |
| 公海客户 | 仅近 30 天跟进 N 次**概览**（不给全文） |
| 本人私海 | 跟单全文 |
| 协同(collaborator) | 全文，且可共同写 |
| 他人私海（本部门/跨部门） | **不可见**（除非协同审批通过） |
| ⚠ 跨部门**同产品线** | **竞争并行，跟单互不可见**（防策略泄露，谁先签约谁得） |

### 4.2 协同 = 共同跟进，不是临时标签
- 通过协同审批自动成为 `collaborator`（可带有效期），协同人可**共同写跟单 + 看全文**。
- ⚠ **别跟"协同标签 coop_tags"（临时@同事喊帮忙、不授读权）混为一谈**——两码事。

### 4.3 交互标准 = 一层抽屉 + 悬浮卡（防叠层，前端 V2.6 §4.3）
- 点公司名 → 开一层抽屉（`.drawer`），**永不叠第二层**。
- 抽屉内点业务线 → **整页跳转** `/relation/detail/:id` 并关抽屉。
- 抽屉内点联系人/销售 → **悬浮卡**（hover + click 钉住；移动端=底部轻面板）。
- **销售悬浮卡只放基础信息，绝不放业绩/名下客户数**。
- 手机号脱敏：非归属部门 = `****{后4位}` +「🔓 申请解锁」→ 走审批（经理批后限时全号）。
- 公司详情页的销售区 = 简版（档案共享 + 别部门电话脱敏）。
- **跟单记录卡片统一显示：填单人 + 跟进联系人**（`createdByName`/`contactName`）。

## 五、台账扩展字段 + 金额脱敏 + 数据权限（系统级铁律）

### 5.1 台账扩展字段（防"字段通胀 + 失控"）
- **主表不加物理列**，扩展值统一存 JSON（`ledger.extra_fields`）。
- **字段先登记元数据表**（field_template 字段模板）才能用，禁止无规则往 JSON 丢 Key。
- **key 与类型一经登记不可改**（🔒）；字段**停用不删除**（停用后置灰，历史数据保留）。
- 台账列 = 通用 8 列 + 各产品线自己的扩展列（由产品线字段模板驱动）。

### 5.2 金额脱敏（跨业务线）
- 库中永远**明文全量**；脱敏只在**应用层渲染**（不脱敏存储）。
- 跨业务线合同/关系金额一律 `***`，仅露"已合作 GEO + 签约日期"这类非金额信息。

### 5.3 数据权限边界
- 销售 = 本人私海 + 公海；经理 = 管辖部门；总经理 = 全部；**他人私海不可见**（除非协同）。
- 越权访问他人私海 = 系统不泄露（列表不出现、搜索搜不到、路由进不去，三层都要挡）。

## 六、撞单 / 竞争 / 状态流转的硬规则（运营 SOP，原型要用界面体现）

| 场景 | 规则（界面要能表达出来） |
| --- | --- |
| 同部门同产品线重复激活 | 后到者申请**转交/协同** |
| 同部门不同产品线 | 并行独立 |
| 跨部门同产品线 | **竞争并行**，跟单互不可见，先签单算谁的 |
| 跨部门不同产品线 | 完全独立 |
| 维护人离职/转岗 | 维护人变更、签单人业绩不变 |
| 客户主动换对接 | 主对接确认 / 经理重分 |

**其它业务不变量**：
- 完成预约必须留跟单记录（服务端强制 422，原型上"完成"按钮要有对应提示逻辑）。
- 公海自动掉落：按业务关系×产品线；**掉海前 24h 推送预警，不"悄悄掉"**（原型呼吸红标预警）。
- 出门登记、报销、续约预警（90/60/30 四级）、工单双分类（售后/商机）。

## 七、信息架构与页面清单（换皮后菜单别跑偏）

> 主导航以**销售动线**为第一原则：上班先看（看板）→ 干活（工作台）→ 查约（预约）→ 管盘子（业务关系）→ 抢无主（公海）。

**一级菜单顺序（换皮后保持不变）**：
数据看板 → 工作台 → 预约管理 → 业务关系 → 录入 → 高级搜索 → 客户管理(系统公海/部门公海) → 客户档案(公司档案/联系人档案) → 合同管理 → 工单管理 → 交付管理(客户台账) → 审批中心 → 报表分析 → 组织架构(员工/部门/产品线/角色/权限) → 系统设置(公海规则/工作流阶段/数据字典)

**全局框架要素（换皮但保留功能）**：
- 侧边栏子菜单**可折叠**（默认只展开当前分组、状态持久化）。
- 顶栏**居中快捷入口**：只放"动作型"（写跟进/新增预约/外出登记/录入客户/公海领取…，≤6 个可自配，点击直接开弹窗或落表单）；数据看板类入口放工作台，不放这里。
- 人员展示 = **头像+姓名+角色小标**；部门/产品线 = **彩色实体标签**（同实体全系统同色）。
- 列表/详情/卡片/弹窗的"该有的字段和按钮"全按前端文档第五章，只是换视觉。

**原型覆盖量（换皮工作量的底）**：约 40 个页面（PC）+ 工作台移动端 1 页。可分批推进，先做 7 个高频页（工作台/数据看板/业务关系列表/业务关系详情/预约管理/录入/公海），跑通新风格后再铺开。
