## 二、真人操作模拟（10 条动线，逐步走）

> 走法：假装我是"某销售/某经理"，按真实顺序点，看**每一步是否顺畅、下一步有没有着落**。

### 动线 1：销售早上开工 → 写第一条跟单 ✅ 基本顺
工作台 → 今日概览 → 点"写跟进" → 弹窗（一句话 + 承诺三快选 + 卡点 + 竞品折叠）。
- ⚠ **卡点**：工作台「今日概览 4 数」**没定义是哪 4 个**（前端 §六只写"4 数"）。
- ⚠ **卡点**：时间轴的「**补单**」是术语黑话，没定义（补写跟单？补录？）。

### 动线 2：电销连续拨打（一天 50 通，大半没接）⚠️ 设计不足
点"快速标记 → 未接电话" → 落库、不重置倒计时 ✅。
- 🔴 **断层**：**"批量"入口没有落点**。工作台是逐条动线、没有可勾选的多选列表；真正要批量的是"公海/关系列表"——但**列表页没设计"勾选 + 批量标记"的交互**（前端 §五 只写了"行操作"）。
- 🔴 **断层**：**没有"电销模式"**。连续打下一个客户 → 打不通 → 标记 → 下一个，这个**流水动作链没有设计**，而这是电销日常主场景。

### 动线 3：经理周一早上看盘 ⚠️ 一屏放不下
看板要装：4 KPI + 今日待跟进 + 状态环形图 + 活跃预警 3 卡 + **目标进度条** + **周重点僵尸榜** + **公海决策待办** + 部门对比 + 销售 TOP。
- 🔴 **断层**：**≥9 块内容**，与《设计规范》§七「一屏一主、减少视觉噪音」**直接冲突**。经理"第一眼该看什么"没有排序。
- 🔴 **断层**：**经理的动线没设计**——周一开周会要什么？月底复盘要什么？现在只有"一个大看板"。

### 动线 4：录入新客户（只拿到手机号）⚠️ 与 3 步流程打架
需求 §6.1 明说「**录入时允许只有手机号，公司名可暂不明确**」。
- 🔴 **矛盾**：前端录入页是**3 步（联系人→公司→确认）**，若"公司可空"，**第 2 步要能跳过**——但页面没设计"跳过公司/暂不明确"的路径与校验。

### 动线 5：撞库命中（4 种分支）⚠️ 只设计了一半
手机号查重命中后，需求 §6.3 有 **4 种分支**：公海可直领 / 本部门已激活 / 跨部门可并行激活 / 挂到现有公司。
- 🟡 **断层**：前端只写了"手机号查重提示"和"公司匹配确认弹窗"，**这 4 分支各自的按钮与文案没逐一设计**，销售遇到会不知道点哪个。

### 动线 6：签约（建合同）✅ 校验来源已补（P0-③）
关系详情 → 点"创建合同" → 需求说**按"本条业务线自己的必填清单"卡**。
- ✅ **已补（P0-③）**：新增 `sign_checklist` 表（挂产品线、管理员配置、系统播种默认清单），三层字段来源（company/relation/ledger）；前端给出"进表单预校验标红 + 提交硬卡 422 + 缺失清单带 goto 锚点"的可视化补全引导（company 级内联补、relation/ledger 级跳补）。落：需求 §7.3 + 接口 §5.15 + 前端 V1.8 页 16~18/25 + 数据架构 §E8。
- 🟡 **断层（仍待设计，非 P0 阻断）**：**业绩分配 UI 缺细节**（怎么选人、合计 100% 怎么校验、默认 signer 100% 怎么显示）——属 P1 细节，不阻塞开工。

### 动线 7：判死一单 → 别人重新领取 ✅ 历史轮次展示已补（P0-④）
判死 → 死因点选（reason=dead）→ 掉回公海（阶段保留）→ 别的销售领取。
- ✅ **已补（P0-④）**：`sea_record` 加 `owner_id`（每轮回海归属人快照），配合 `business_relation` 重新领取级联（open 承诺 `owner_id` 转新 owner）。界面新增「历史轮次」区块（第 N 轮徽标 + 上一轮卡片：原归属人/掉海原因/跟单数/时间）+ 重新领取横幅"本关系已于 XX 由 XX 判死，现由您重新跟进，上一轮跟单已归档可展开查看"。数据来自 `GET /relations/:id/rounds` 与 `prev_round`。落：需求 §8.1 + 接口 V1.8 + 前端 V1.12 页 6 + 数据架构 §F2/C3。

### 动线 8：领取公海后的跟单视图 ✅ 前主人归组已补（P0-⑤）
领取 → 继承全文跟单。新 owner 自己没填过，历史跟单原属前主人。
- ✅ **已补（P0-⑤）**：`action_event` 加 `owner_snapshot`（每条跟单创建时关系 owner 冗余快照）。跟单先按**归属轮次**分段（`round_no` 派生＝已掉海次数+1），轮次内按 `owner_snapshot` 归组——**本轮 owner 走主线/树杈，前主人轮次标原归属人姓名**；新 owner 本轮尚无跟单时顶部显示"以下是前主人记录，仅供参考"横幅。一条跟单两个视角（owner 主线 vs 前主人归组）同源、不重复存。落：需求 §7.5 + 接口 V1.8 事件项 DTO + 前端 V1.12 页 6 + 数据架构 §D2。

### 动线 9：看自己的目标进度 ⚠️ 销售侧缺入口
需求 §7.11：目标由经理填，**销售只看自己**。
- 🟡 **断层**：**销售在哪看自己的月目标进度？** 数据看板/工作台都没明确"个人目标条"的落点（目标页 26 是经理/老板视角）。

### 动线 10：交付/客服 / 管理员登录 ⚠️ 角色视角缺失
需求 §4.1 有 5 个角色（销售/交付客服/部门经理/总经理/管理员），但 29 页几乎是**"销售 + 经理"视角**。
- 🔴 **断层**：**没有「角色 × 页面可见性矩阵」**。交付/客服登录后看到什么菜单、能操作什么？管理员呢？总经理呢？全都未定义——**这是最大的一个设计缺口**。
