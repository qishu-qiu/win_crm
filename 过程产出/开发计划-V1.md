## 二、目标与范围

### 2.1 V1 目标（＝需求 §14.1）

打通「**登录 → 建公司/联系人 → 建业务关系 → 写跟单 → 工作台看到它**」这条动线（穿透 A/B/C/D 四域）→ 让真实销售**能开始试用**；随后按域补齐 V1 全部功能。

### 2.2 明确不做（**防走偏清单**，动手前先记牢）

**范围级（需求 §14.2）**：客户出口 / 报销审批 / 介绍费·提成分账 / 客户地图·附近客户·顺路推荐 / 自动处境引擎 / 竞品价格表·功能对照档案库 / 自动地址解析 / 拜访 GPS 校准 / 外部工商数据源对接。

**实现级（需求 §十六，★ 规范级 · 完整清单）**：如**承诺不做独立录入页**、**阶段绝不自动改**、**客户等级不可手填**、**掉公海只掉一步**、**@求助限同部门**、**跟单分界＝owner 不是登录人**、**快速标记不重置掉海倒计时**、**无任何自动删除/自动流转**、**报表出口不脱敏**……

> **本段不复制规则本体**，只作任务计划时的"封路提醒"；**实现边界一律以 §14.2 与 §十六 为准**（"表里没有"才代表允许）。

### 2.3 完成定义（DoD，每个里程碑都适用）

1. `npm run lint` 通过（**模块边界硬卡**，故意跨域 import 必须报错）；
2. 涉及的业务铁律有**单测**（`domain/` 纯函数用假数据）且 `npm test` 绿；
3. 接口在 `/docs`（OpenAPI）可见、响应符合接口 §二 统一包与 §五 数据结构；
4. 一次**可提交的还原点**（README §三：直接 `main`，提交信息写"改了什么/为什么/联动哪些文档"）；
5. 本次变更若触动业务规则 → **先改需求文档，同批联动接口/前端/数据架构，同一次提交完成**（README §八 L0 铁律）。
