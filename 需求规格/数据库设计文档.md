**设计三铁律**：
1. **主表不动态新增物理列**——台账扩展值统一存 `extra_fields` JSON 列
2. **先登记、后写入**——所有自定义字段必须先登记 `field_template` 元数据表，写入时校验，未登记 Key 拒收
3. **业务关系唯一性靠数据库唯一索引兜底**——不靠应用层自觉

**通用约定**：
- 主键统一 `id` BIGINT UNSIGNED AUTO_INCREMENT
- 审计字段全表统一：`created_by / created_at / updated_by / updated_at`，逻辑删除 `deleted_at`（NULL=未删）
- 金额统一 `DECIMAL(12,2)`；时间统一 `DATETIME`；枚举存 `VARCHAR(32)` 英文码，展示文案走数据字典
- 租户/脱敏不做库级隔离，由应用层按管辖部门过滤

## 二、ER 总览

```
department ─┬─< employee >─┬─ employee_role ─ role
            │              └─ dept_manager（管辖部门 N:M）
            └─ dept_rule（部门规则：等级档位/灰度寿命，V1.1）
product_line ─┬─ field_template（台账字段元数据）
              └─ sea_rule（公海规则 L1-L4）
company ─┬─< company_contact >─ contact ─ contact_change_log
         │                        └─ contact_trait（谈判特质 ≤3，V1.1）
         ├─ company_profile_tag（画像：身份/制度/决策链，V1.1）
         └─< business_relation >─┬─ relation_member（主对接/维护人）
                                  ├─ relation_stage_log（6 步跳级/回退留痕，V1.1）
                                  ├─< follow_record ── visit_log（外出）
                                  ├─< appointment
                                  ├─< contract ─< payment_record
                                  ├─< workorder ─< workorder_log
                                  └─< sea_record（入公海历史）
contract ─< ledger（+extra_fields JSON）
approval（转交/协同/手机号变更/报销 四型一单）
dict_type ─< dict_item ｜ workflow_stage（6 步种子）｜ notification ｜ operation_log
```

## 三、组织与权限域

### 3.1 department 部门表
| 字段 | 类型 | 说明 |
|---|---|---|
| name | VARCHAR(64) | 部门名 |
| parent_id | BIGINT | 上级部门，0=根 |
| service_enabled | TINYINT(1) | 启用客服开关 |
| status | VARCHAR(16) | active/disabled |

### 3.2 employee 员工表
| 字段 | 类型 | 说明 |
|---|---|---|
| work_no | VARCHAR(32) | 工号，UNIQUE |
| name / phone / password_hash | — | 手机号 UNIQUE |
| primary_dept_id | BIGINT | 主部门 |
| extra_dept_ids | JSON | 兼部门 ID 数组 |
| product_line_ids | JSON | 关联产品线 |
| direct_manager_id | BIGINT | 直属经理（审批转单用） |
| status | VARCHAR(16) | active/resigned/disabled |

### 3.3 dept_manager 管辖部门表（多对多）
`dept_id + employee_id`，联合唯一。**"本部门"权限语义的全部来源**：经理查数据范围 = 此表其管辖部门列表。

### 3.4 role / employee_role
- role：`code`(sale/service/delivery/admin/dept_manager/gm) + name + is_builtin=1；V1 仅 6 条内置
- employee_role：`employee_id + role_code` 联合唯一（多角色）

### 3.5 permission_matrix 权限矩阵
| 字段 | 说明 |
|---|---|
| perm_key | 权限项（如 cross_dept_private / contract_amount） |
| role_code | 角色 |
| level | ENUM(visible, masked, denied) |

### 3.6 product_line 产品线表
| 字段 | 类型 | 说明 |
|---|---|---|
| name / code | — | code UNIQUE |
| dept_ids | JSON | 承接部门 |
| service_cycle_days | INT | 服务周期 |
| sea_default_freq / sea_default_deal / sea_default_stay | INT | 公海默认值（跟进频次/成单周期/停滞天数） |
| status | — | |

## 四、客户资产域

### 4.1 company 公司表
| 字段 | 类型 | 说明 |
|---|---|---|
| full_name | VARCHAR(128) | 公司全称，INDEX；查重用 FULLTEXT 或 trigram 相似度 |
| credit_code | VARCHAR(18) | 统一社会信用代码，UNIQUE（允许 NULL，撞码强制使用已有） |
| industry_l1/l2, province/city/district, scale | — | 地区行业规模 |
| completeness_1/2/3 | TINYINT | 三档完善度 0-100（写入时重算） |
| website / address / bank_name / invoice_title / tax_no | — | 成交后强制组 |

### 4.1a company_profile_tag 公司档案标签表（V1.1）
| 字段 | 类型 | 说明 |
|---|---|---|
| company_id | BIGINT | 公司，INDEX |
| group_code | VARCHAR(32) | company_identity_tag（身份，多选）/ company_policy_tag（制度，多选）/ decision_chain（决策链，单选） |
| tag_id / tag_code | BIGINT / VARCHAR(64) | 选项引用（tag_id 关联 O14 标签字典；tag_code 冗余防字典改名） |
| marked_by / marked_at | BIGINT / DATETIME | **打标人留痕**（"XX 于 09-07 标记"） |
| **联合唯一** | | `uk(company_id, group_code, tag_id)`；`decision_chain` 单选由应用层保证每组仅 1 条 |

> 建档时人工勾一次、全公司共享（不随业务关系/部门隔离）；后端按 G10 全量覆盖更新，删除即物理删行（历史留痕见 operation_log）。

### 4.1b dept_rule 部门规则表（V1.1，N12）
| 字段 | 类型 | 说明 |
|---|---|---|
| dept_id | BIGINT UNIQUE | 部门（仅该部门经理可配） |
| level_tiers | JSON | 客户等级金额档位：`[{level:A/B/C/D, minAmount}]`（**每部门各自定义**，回款到账事务内按本表算等级） |
| gray_remind_days | INT | 灰度 N 天未定性 → 提醒销售下结论 |
| gray_release_days | INT | 再 M 天未动 → 列为公海释放候选（`business_relation.gray_release_at` 置位），经理确认后释放 |
| updated_by / updated_at | — | 写 operation_log |

### 4.2 contact 联系人表
| 字段 | 类型 | 说明 |
|---|---|---|
| name | VARCHAR(30) | |
| phone | VARCHAR(11) | **UNIQUE，撞单校验核心** |
| wechat / email / gender / birthday | — | |
| decision_role | VARCHAR(16) | decision/influence/execute |
| tags | JSON | 个人自由标签（爱喝茶/老板亲戚…，V2.5 起与谈判特质**分栏并存**） |
| status | VARCHAR(16) | active/left/freelance |
| phone_frozen_until | DATETIME | 手机号变更审核冻结期（24h） |

### 4.2a contact_trait 联系人谈判特质表（V1.1，G11/G12）
| 字段 | 类型 | 说明 |
|---|---|---|
| contact_id | BIGINT | 联系人，INDEX |
| trait_id / trait_code | BIGINT / VARCHAR(64) | 选项引用（contact_trait 字典，价格敏感/关系型/方案型/专业控…可自定义） |
| marked_by / marked_at | BIGINT / DATETIME | 打标人留痕 |
| **联合唯一** | | `uk(contact_id, trait_id)`；**每人 ≤3**（应用层校验，超出 422+20402） |

> 特质存 **contact 层**（不存 company_contact 就职表）——**跟着人走，换公司保留**；G12 全量覆盖更新。

### 4.3 company_contact 就职关系表（N:M 含历史）
`company_id + contact_id + is_current + joined_at + left_at + position`；一个人多家公司、历史就职全留痕。

### 4.4 contact_change_log 联系人变更留痕
`contact_id + field + old_value + new_value + approval_id + created_at`；手机号变更必须关联审批单。

## 五、业务关系域（核心）

### 5.1 business_relation 业务关系表
| 字段 | 类型 | 说明 |
|---|---|---|
| company_id / dept_id / product_line_id | BIGINT | 三元组 |
| status | VARCHAR(16) | data/intent/customer/renew/lost |
| stage_id | BIGINT | 工作流阶段（workflow_stage，6 步状态机） |
| **urgency** | VARCHAR(16) | **紧迫档（V1.1）**：weekly/monthly/quarterly/long_term/**gray（默认）**；纯手动，无自动降级 |
| **value_level** | VARCHAR(16) | **业务线价值（V1.1）**：high/medium/low/**pending（默认空）**；手动，愿意标才标 |
| value_estimate | DECIMAL(12,2) | 价值评估（金额，与业务线价值 value_level 是两套：本字段为合同金额口径的评估值） |
| customer_level | CHAR(1) | A/B/C/D（回款金额按**本部门 dept_rule 档位**自动计算） |
| **gray_release_at** | DATETIME NULL | **灰度寿命释放候选时间戳（V1.1）**：命中 dept_rule.release_days 置位；NULL=未进入预警；经理确认释放后清空并置 sea_status |
| **risk_tags_manual** | JSON | **人工补风险标签（V1.1）**：`[{code,label,markedBy,markedAt}]`（流失信号/回款风险等人工补打；auto 项不落库，由 O16 规则实时派生并只读回传） |
| **coop_tags** | JSON | **协同标签（V1.1）**：`[{code,label,mentionedUserIds[]}]`（需陪访/需技术支持/需方案支持，手动，可 @ 同事） |
| last_follow_at / next_follow_at | DATETIME | 跟进双时间，INDEX（预警任务扫描） |
| no_progress_count | INT | 连续无推进次数（掉公海判定） |
| sea_status | VARCHAR(16) | private/dept_sea/company_sea |
| lost_reason | VARCHAR(255) | 流失必填 |
| **唯一索引** | | `uk_active_rel (company_id, dept_id, product_line_id, sea_status)` 配合部分唯一策略：**同一公司+部门+产品线仅允许一条私海活跃关系**（MySQL 用生成列 `active_key` 实现：私海时=三元组，否则=NULL，对 active_key 建唯一索引） |

### 5.1a relation_stage_log 阶段推进留痕表（V1.1）
`relation_id + from_stage_id + to_stage_id + action(normal/jump/rollback/lost) + reason + operator_id + created_at`；**跳级/回退/异议无解双出路（回落长期跟 or 判流失）全量落此表**；E06 返回的 resolveOptions 双出路落地后均在此留痕。

### 5.2 relation_member 关系成员表
`relation_id + employee_id + member_type(owner/maintainer)`；签单人锁定、维护人可变更。

### 5.3 follow_record 跟单记录表
| 字段 | 说明 |
|---|---|
| relation_id / contact_id / created_by | 关联 |
| follow_at / method(phone/wechat/visit/onsite/email) | |
| summary TEXT / attitude / progress | 摘要+态度+进展 |
| next_action | 下一步 |
| attachments JSON | 附件 |
| visit_log_id | **外出关联（🚗 标记来源）** |
| idempotency_key UNIQUE | 防重复提交 |

### 5.4 appointment 预约表
`relation_id + appointment_at + note + status(pending/done/rescheduled/expired_archived) + follow_record_id(完成时强制关联)`；改期留 `reschedule_log` JSON。

### 5.5 visit_log 外出登记表
`employee_id + relation_ids JSON + depart_at + expect_return_at + actual_return_at + purpose + transport + companions JSON`；关联报销审批单 `approval_id`。

## 七、交易与服务域

### 7.1 contract 合同表
`contract_no UNIQUE + relation_id + product_line_id + contact_id + signer_id（签单人锁定） + maintainer_id + amount + paid_amount + pay_type + sign_date + service_start/end + auto_renew + remind_days JSON(30/60/90) + attachments JSON + status(unpaid/partial/running/done/terminated)`

### 7.2 payment_record 回款流水
`contract_id + amount + paid_at + method + voucher_file_id + created_by`；回款写触发器/事务更新 `contract.paid_amount` 与状态。

### 7.3 workorder / workorder_log
- workorder：`order_no UNIQUE + type(aftersale/opportunity) + relation_id + title + content + source + priority(P0-P3 仅售后) + assignee_id + sla_deadline + status(created/assigned/processing/confirming/closed) + upgraded_from_id（升级互链）`
- workorder_log：`workorder_id + action + from_status + to_status + reason + operator_id`（升级必填原因留痕）

### 7.4 ledger 客户台账表（铁律落地点）
| 字段 | 类型 | 说明 |
|---|---|---|
| contract_id / company_id / product_line_id | BIGINT | 来源 |
| customer_level / sign_date / expire_date | — | 通用字段（共 8 项，含联系人/交付对接人/销售对接人/备注） |
| **extra_fields** | **JSON** | **扩展字段值唯一存放地；Key 必须存在于 field_template，写入校验，未登记拒收** |
| 索引 | | `(product_line_id, expire_date)`；如需按扩展字段统计，对高频 Key 建**生成列+索引**（由 DBA 评估后逐个加，仍不动主表结构） |

### 7.5 field_template 字段元数据表（登记唯一入口）
| 字段 | 类型 | 说明 |
|---|---|---|
| product_line_id | BIGINT | 归属产品线 |
| field_key | VARCHAR(64) | **保存后不可变**；`uk(product_line_id, field_key)` |
| label / control_type(text/number/date/select/multiselect/link) | — | control_type 保存后不可变 |
| required / sort / show_in_list | — | 可改 |
| options | JSON | select/multiselect 选项 |
| status | VARCHAR(16) | active/**disabled（停用不删除，历史值照常展示）** |

## 八、审批与系统域

### 8.1 approval 审批表（四型一单）
| 字段 | 说明 |
|---|---|
| type | transfer / collaborate / phone_change / reimburse |
| applicant_id / approver_id | 申请人/审批人（不可同一人，DB CHECK+应用双拦） |
| target_type / target_id | 审批对象（关系/联系人/报销单） |
| payload | JSON（转交目标人、新旧手机号、报销明细等） |
| status | pending/approved/rejected |
| comment / handled_at | 驳回必填原因 |

### 8.2 notification 通知表
`user_id + title + content + biz_type + biz_id + channel(site/wechat) + read_at`；**channel 字段即微信推送预留位**，V1 只写 site。

### 8.3 dict_type / dict_item
字典项 `builtin=1` 不可删（仅停用）；修改写 operation_log。

### 8.4 workflow_stage 工作流阶段表
`dept_id + product_line_id + name + sort + is_final + status`；被引用阶段 status 只能 disabled 不能删（引用计数应用层校验）。
- **V1.1 6 步状态机种子**（对齐接口 V1.3 / 前端 V2.5，按部门×产品线初始化）：`1 初步建联 → 2 需求确认 → 3 面访产品讲解 → 4 异议与卡点 → 5 逼单 → 6 已合作（is_final）`；步骤允许跳级/回退（E06），推进记录落 `relation_stage_log`（5.1a）

### 8.5 operation_log 操作日志
`operator_id + action + target_type + target_id + detail JSON`；激活/转交/规则/字典/权限矩阵/字段模板修改全量落。

## 九、关键索引与并发设计

| 场景 | 设计 |
|---|---|
| 撞单 | `contact.phone` UNIQUE + `company.credit_code` UNIQUE；公司名相似度应用层算 |
| 激活竞态 | `business_relation.active_key` 生成列唯一索引——后到者 INSERT 撞 1062，转 409 返回归属人 |
| 编辑并发 | 各主表 `updated_at` 作乐观锁版本戳，更新带条件，影响 0 行即 409 |
| 预警扫描 | `business_relation(next_follow_at, sea_status)`、`contract(service_end, status)`、`workorder(sla_deadline, status)` 复合索引支撑定时任务 |
| 管辖部门过滤 | 全部列表查询强制 `dept_id IN (管辖部门集合)`，集合登录时注入缓存 |
| 掉公海判定 | 定时任务按命中规则扫描：`now - last_follow_at > follow_freq_days` 或 `no_progress_count >= no_progress_max` 等，掉落写 sea_record + notification |
| 灰度寿命预警 | 定时任务扫描 `urgency=gray & gray_release_at IS NULL & now - last_follow_at > dept_rule.gray_remind_days` → 发提醒（P07 type=risk）；再超 `gray_release_days` → 置 `gray_release_at` 列为公海释放候选，经理确认后释放（写 sea_record） |

## 十、数据安全与脱敏

- 手机号列表查询默认 `CONCAT(LEFT(phone,3),'****',RIGHT(phone,4))` 应用层处理，全量仅详情按权限返回
- 跨业务线金额/跟单脱敏在应用层按 permission_matrix 渲染，**库中永远是明文全量**（不脱敏存储，保证归属方可用）
- 合同页水印、操作日志为应用层责任
