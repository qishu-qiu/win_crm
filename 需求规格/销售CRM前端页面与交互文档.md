## 一、文档体系与铁律

### 1.1 与四件套关系
- 本文件只定义「**有哪些页、页面级怎么交互**」。**视觉/组件/状态见《设计规范》**；业务规则见 `→需求§X`，接口契约见 `→接口API§Y`，表结构见 `→架构表Z`。
- **同一事实只定义一次**（L1）：本文件不重复 token、枚举、错误码。

### 1.2 元铁律
- **L0 变更联动**：业务/接口一改，本文件同批改、同批升版。
- **信息架构不可动**（E3）：一级菜单顺序见 §四，换皮不许改。
- **★ 对齐铁律（2026-09-10 立）**：**需求/接口里定义的每一个动作、配置、复盘类功能，都必须在本文件有明确页面或章节落点**；新增功能不得只写进业务/接口而不落前端。

### 1.3 设计基准
- 视觉基准＝ **Ant Design 5**（详见《设计规范》§二）；本文件的页面交互**遵循《设计规范》全部铁律**（token 统一 / 反 AI 味 / 三态完整 / 响应式）。
- 数值、组件、状态、响应式、层级、主题**一律以《设计规范》为准**，本文件不另立。

## 三、设计总则（交互）

### 3.1 实体可点 + 一层抽屉 + 悬浮卡（A1~A7，[铁律]）
1. 公司/联系人/员工**任何位置**名称都可点（A1）；禁纯文本不可点（当前页即该实体详情页除外）。
2. 点公司 → **一层抽屉**，**永不叠第二层**（A2）。
3. 抽屉内点业务线 → 整页跳 `/relation/detail/:id` 并关抽屉；点联系人/销售 → **悬浮卡**（hover+click 钉住）（A3）。
4. **销售悬浮卡只放基础信息**，不放业绩/名下客户数（A4）。
5. 联系人悬浮卡含手机号脱敏+谈判特质+决策角色（A5）。
6. 跟单卡片统一显示「填单人+跟进联系人」且都可点（A6）。
7. 移动端悬浮卡 → 底部轻面板 `.sheet`，不叠抽屉（A7）。

## 四、信息架构与菜单（E1~E3）

一级菜单顺序（**固定，不可改**）：
`数据看板 → 工作台 → 预约管理 → 业务关系 → 录入 → 高级搜索 → 客户管理(系统公海/部门公海) → 客户档案(公司档案/联系人档案) → 合同管理 → 工单管理 → 交付管理(客户台账) → 审批中心 → 报表分析 → 组织架构(员工/部门/产品线/角色/权限) → 系统设置(公海规则/部门规则/工作流阶段/节奏规则/数据字典)`

- **目标与进度**：`→需求§7.11`，**经理/老板可见**，入口挂在「数据看板 / 报表分析」内，个人路由 `/target`。
- **消息中心**：不做一级菜单，走**顶部铃铛**（未读角标）→ `/notifications`。
- **个人中心 / 外观设置**：顶部头像菜单 → `/me/appearance`。
- **先做 7 高频页**（工作台/看板/业务关系列表/详情/预约/录入/公海）跑通新风格再铺开（E2）。
- 侧栏子菜单可折叠、状态持久化（D1）；顶部快捷入口 ≤6 动作型（D2/D3）。

**四条落地规则**：
1. **"服务中"的定义**（交付/客服范围）＝ 有在办工单 **或** 处于服务期内的业务关系（`→需求§4.2`）。
2. **管理员看业务数据的护栏**：一律**只读**；**所有查看动作写 `operation_log`**；**不解除脱敏**（`→需求§4.2`）——方便排障，不留"无痕看全公司"的口子。
3. **快捷入口按角色模板下发**（D3）：销售默认 4 个；经理追加「待我审批」；**交付/客服只给工单相关动作**（新建工单 / 待处理工单），不给"写跟进 / 录入客户"。
4. **实现口径**：菜单与按钮可见性由 **role ＋ `permission_matrix`** 决定；**不可见的页面不下发路由**（不是"显示了再禁用"），越权访问返回 403（`→接口API§2.2`）。

## 六、单页关键需求

> 标注：`A~I`=历史清单编号；`→需求§`=业务规则；`→接口API§`=接口；视觉/组件细节见《设计规范》。

**1 登录 /login**：账号+手机验证码/密码；亮色简洁（B2）；错误态红（B5）；登录后按角色跳看板/工作台。

**2 数据看板 /dashboard**（A/H）：4 KPI（今日新增/今日待跟进/本月签约含环比红涨H1/名下关系数）；左「今日待跟进」逾期红置顶；右状态环形图；活跃预警 3 卡（签约到期/掉公海呼吸红/新商机）。
- **目标进度条**（经理/老板）：主指标＝**回款额**完成率，旁挂「签约额 XX 万」；条下「时间已过 X%」＋领先/落后点数——**领先绿 / 持平橙 / 落后红**（`→需求§7.11`）。
- **周重点僵尸榜**：挂 ≥2 周无推进的周重点客户＋负责人（`→需求§8.2`）。
- **公海超期决策待办**（经理）：保留 / 删除（逻辑删留痕 `→需求§6.3`）。
- **客户等级分布**：S/A/B/C/D，**必须标「条」还是「家」**（`→需求§8.3`）。

**3 工作台 /workbench**（B6/A/D）：今日概览 4 数 + 动作条直通（写跟进主按钮 ＋ 外出登记）+ 今日安排时间轴（逾期置顶红+补单/改期直达）+ 本周重点卡片「去跟进」。
- **外出登记**：动作条按钮 → 弹窗三样（出去时间 ＋ 去干什么 ＋ 可选关联关系）；**回来点一下**（`→需求§7.5`）。
- **快速标记批量**：勾选多客户 → 一次性标记（未联系/未接/说两句）；落库但**不算有效跟进、不重置掉海倒计时**。
- **同类提醒合并**：相同类型+原因合并成一条，点开看明细（`→需求§10.4`）。

**4 预约管理 /appointment/:tab**（A/H）：4 Tab（今日/未来/过期红 count/未预约）；表格含距掉公海 X 天倒计时；过期行 `row-danger`；行操作写跟进/改期/完成预约（完成强制生成跟单，否则 422）；默认显「过期」Tab 红色警示。

**5 业务关系列表 /relation/list**（A/C/H）：seg 视图（我的全部/跟进中/已合作/已流失/逾期未跟进 ＋ 紧迫档 5 档）；列表含阶段彩色点、逾期红、24h 掉公海⚠、跨线 `amount_masked`、竞争徽标、客户等级徽标、开发价值软档、价值 ¥千分位 H2；分页；实体可点（A1）。
- **紧迫档筛选与设置**：5 档 chip（周重点红/月重点橙/季度跟蓝/长期跟绿/灰度灰）；批量「标记紧迫档」。
- **周重点闭环**：挂满 2 周无推进 → 强制二选一（推一把/降级/判死）。
- **等级 vs 价值分列**：客户等级＝S/A/B/C/D 系统自动（⚙）；开发价值＝高/中/低/待定 手动软档（`→需求§8.3`）。

**6 业务关系详情 /relation/detail/:id**（A/D）：顶部信息卡；操作按钮组（写跟进/新增预约/激活/转交/创建合同禁用态+提示/创建工单/判死/流失）；**8 Tab**：基础 / 跟单 / 工作流 / 拜访外出 / 合同 / **工单（含商机 type=opportunity）** / 关系网 / 复盘；跟单 Tab 默认展开，**时间轴按「归属轮次」分组**（一轮＝一次私海→掉回公海，轮次号＝已掉海次数+1 派生）：先以轮次分段，轮次内以 owner 分界为主线/树杈；**前主人轮次的跟单按 `owner_snapshot` 归组并标原归属人姓名**，新 owner 本轮尚无跟单时顶部显示「以下是前主人记录，仅供参考」横幅（→需求§7.5 / §8.1 / 接口 `GET /relations/:id/rounds`）；右侧「同公司其他关系」脱敏卡。**多联系人（`→需求§6.3` V1.17）**：一条关系可同时跟多个联系人（老板/招商/财务），**每人每次一条、时间轴按时间混排、不按人分组**；写跟单的「跟进联系人」**选填**，该关系已有联系人时**默认带出上次跟进的联系人**（一点即选、不选也可提交，不硬卡）；见谁都算有效跟进，不按角色加权；**跟单 Tab 顶部一排联系人芯片（含「全部」），点选只看该联系人的跟单**（纯展示、免翻全时间线，`→需求§6.3`）。
- **判死/流失**：见《设计规范》§四.9 复盘弹窗。判死→掉回公海、阶段保留；流失→掉回公海、阶段置 7（`→需求§8.1`）。
- **历史轮次区块 + 重新领取横幅（P0-④⑤）**：业务关系详情新增「历史轮次」折叠区，展示第 N 轮徽标 + 上一轮卡片（原归属人/掉海原因/跟单数/时间）；重新领取后顶部显示「本关系已于 YYYY-MM-DD 由 XX 判死/流失、现由您重新跟进，上一轮跟单已归档可展开查看」横幅（→需求§8.1 / 接口 `prev_round` / `GET /relations/:id/rounds`）。
- **标签区**（关系级）：风险/价值/协同/coop 打标；coop 临时 @ 不授读权（`→需求§9`）。
- **竞品区**：「这单有竞品吗？」折叠一行，默认无跳过；三分关系系统推导、销售不标（`→需求§11.1`）。
- **阶段推进**（工作流 Tab）：动作驱动 + 建议态 + 一键确认 + 限频（≥3 天或跨里程碑）+ 留痕（`→需求§8.1`）；**回退（rollback）触发经理知会**（`notification.biz_type=stage_revert`，经理只知会不审核不拦截，`→需求§8.1`）。
- **成员区**：owner ＋ collaborator（可带有效期）＋ ask_help 临时 @（默认 7 天收回）。

**7 录入 /entry/new**（A/E）：3 步步骤条（联系人→公司→确认）。
- **第 2 步「公司」可跳过**：选「暂不填公司，先存为待跟进」→ 只建联系人＝「待关联公司」（见需求 §6.1 模型 B）；补全路径：联系人详情「关联公司」→ 走撞库 → 激活关系。
- **撞库 4 分支**（手机号 / 公司名·信用代码查重命中即弹，见需求 §12.1）：①公海可直领 ②本部门已激活（联系张三/申请转交/申请协同）③跨部门可并行（只显部门名+日期，不露跟单）④挂现有公司（使用已有/确认新建，疑似重复必须给强行新建出口）；分支 2 转交次推且走审批，分支 4 强行新建留痕+经理看板提示。
- 手机号查重提示；公司匹配确认阻断弹窗。

**8 高级搜索 /search/advanced**（G7）：说明条「数据范围：您管辖的 N 个部门」；筛选（关键词/部门/成员/产品线/状态/时间段）；结果含所属部门+归属成员；「不支持导出」；空态。

**9/10 系统公海 / 部门公海**（A/D）：筛选栏；3 列卡片流（公司名/地区·规模·行业/联系人脱敏、进入时间、进入原因 tag、剩余 X 天倒计时）；卡片「查看详情/领取到私海」（幂等）；未领只显概览不显跟单全文。
- **老客户徽标**：派生（有历史合同即显示，不加字段）。
- **入公海历史**：时间/原因/原归属（`owner_id`，每轮回海归属人快照，→架构 F2）；判死（dead）/流失（churn）原因与「历史轮次」区块同源（P0-④⑤）。
- **经理决策待办**：超期关系 保留/删除。

**11~13 公司档案**（A/D）：列表显「地址是否维护」（派生）；详情一层抽屉简/全版分角色；编辑含公司档案标签（身份/制度/决策链）；经纬度人工地图拾取（非必填）。

**14/15 联系人档案**（A/D）：列表人员芯片 mini；**列表支持筛选「未关联公司」**（＝待关联，见需求 §6.1）；详情含谈判特质（≤3，超限 422）、决策角色；**详情顶部「⚠ 尚未关联公司」横幅 + 「关联公司」入口**；悬浮卡。

**16~18 合同管理**（A/H）：整页水印；4 KPI；付款流水时间轴+添加回款（凭证指 `file_asset`）；归属卡（签单人🔒/维护人可变更）；续约预警 90/60/30 四级；跨线合同区金额 `***` 脱敏；合同业绩分配（默认 signer100%，合计100%）。
- **★ 签约校验交互（P0-③，见需求 §7.3 / 接口 §5.15）**：进签合同表单**先预校验**——顶部红色横幅「签约前还需补全 N 项」+ 缺失字段标红；点提交任一缺失**硬卡 422**（`missing` 清单带 scope/label/goto）。**补全方式**：`scope=company` 缺失项（信用代码等）在弹窗内**直接内联填**（不跳出签合同页，最快）；`scope=relation` 缺开发价值→「去补全」跳关系详情标 `value_tier`；`scope=ledger` 缺字段→「去补全」跳台账编辑页；补完回签合同页**自动重校验**。`scope=company` 字段共享（有值即过，不论谁补）。

## 九、交互规范（★）

### 9.1 hover（只做轻微背景变化）
- 表格行/列表项 hover：`--color-bg-hover`（`rgba(0,0,0,.04)`）。
- 文字按钮 hover：背景 `rgba(0,0,0,.06)`；链接 hover：`--color-primary-hover`。
- **硬禁**：hover 放大、位移、发光、阴影增强、渐变、颜色跳变。

### 9.2 点击反馈
- 所有可点元素有 active 态（背景加深/主色 `--color-primary-active`）。
- 行点击：整行可点（进详情）时行 hover 光标变手型；行内操作阻止冒泡。
- 异步操作点击后立即进入 loading（防重复点击）。

### 9.3 校验与提示
- 即时校验（blur）+ 提交校验；错误消息**指明原因与修正方式**。
- 危险操作（删除/判死）二次确认，确认按钮用 danger。

### 9.4 防抖 / 幂等
- 搜索输入 **300ms 防抖**；提交类请求带幂等键（`→接口API§2.5`）。
- 按钮 loading 期间禁用。

### 9.5 键盘与无障碍
- 焦点环：3px `--color-primary`（AntD `lineWidthFocus`）；Tab 顺序符合视觉流。
- `Esc` 关闭弹层；`Enter` 提交（表单）；下拉支持方向键。
- 对比度 ≥ 4.5:1；**不单靠颜色表意**；图标按钮带 `aria-label`。

## 十五、验收标准

**对齐 / 功能**
- 实体可点：列表/卡片/跟单/审批/报表中无任何不可点公司名/人名（A1）。
- 抽屉只一层、悬浮卡不叠（A2/A3/A7）；销售悬浮卡无业绩/客户数（A4）。
- 跟单卡显示填单人+联系人且可点（A6）。
- 脱敏三处正确：跨线金额 `***`、非归属手机 `****后4`、公海未领不显全文（G4/G5）。
- 涨红跌绿、¥千分位+等宽数字（H1/H2）。
- 移动端仅工作台、底部 Tab、轻面板（F1~F3）。
- **主题：白天 / 夜间两套生效、个人外观持久化**（A/B/C 风格后置，不进 V1）。
- **无功能悬空**：判死/流失/复盘、目标、消息中心、节奏规则、外出登记、公海经理决策，六项缺一不可验收（§一.1.2 对齐铁律）。
- 紧迫档可设可筛；挂满 2 周强制二选一；等级（系统自动⚙）≠ 价值（手动软档）分开渲染、报表标「条/家」。
- 低摩擦录入：写跟单 ≤10 秒（一句话 + 承诺三快选）；快速标记可批量且不重置掉海倒计时。
