## 一、文档体系与铁律

### 1.1 与四件套关系
- 本文件只定义「**长什么样、怎么交互**」。业务规则见 `→需求§X`，接口契约见 `→接口API§Y`，表结构见 `→架构表Z`。
- **同一事实只定义一次**（L1）：枚举/错误码/脱敏口径只写「见《接口 API 文档》§二」，不复制。

### 1.2 元铁律
- **L0 变更联动**：业务/接口一改，本文件同批改、同批升版。
- **信息架构不可动**（E3）：一级菜单顺序见 §三，换皮不许改。
- **★ 对齐铁律（2026-09-10 立）**：**需求/接口里定义的每一个动作、配置、复盘类功能，都必须在本文件有明确页面或章节落点**；新增功能不得只写进业务/接口而不落前端。

## 二、设计总则（[铁律]+[方向]，逐条对应历史清单）

### 2.1 实体可点 + 一层抽屉 + 悬浮卡（A1~A7，[铁律]）
1. 公司/联系人/员工**任何位置**名称都可点（A1）；禁纯文本不可点（当前页即该实体详情页除外）。
2. 点公司 → **一层抽屉**，**永不叠第二层**（A2）。
3. 抽屉内点业务线 → 整页跳 `/relation/detail/:id` 并关抽屉；点联系人/销售 → **悬浮卡**（hover+click 钉住）（A3）。
4. **销售悬浮卡只放基础信息**，不放业绩/名下客户数（A4）。
5. 联系人悬浮卡含手机号脱敏+谈判特质+决策角色（A5）。
6. 跟单卡片统一显示「填单人+跟进联系人」且都可点（A6）。
7. 移动端悬浮卡 → 底部轻面板 `.sheet`，不叠抽屉（A7）。

### 2.2 视觉方向（B1~B8，[方向] 2026-09-09 推翻重做）
- **B1** emoji 全砍，统一 Feather 线性图标（语义不丢）。
- **B2** 大留白、浅色、一屏一主次。
- **B3** 主色只给可点按钮。
- **B4** 侧栏砍到销售日常 6 项 + 管理收进「更多」。
- **B5** 红色只给逾期/风险。
- **B6** 工作台 = 今天动作唯一入口。
- **B7** 卡片堆叠收敛。
- **B8** 高端大气、简单舒适、降学习成本。

### 2.3 换肤（C1~C4，[铁律-色彩]）
- 亮度（light/dark）× 风格（A 紫蓝 / B 深藏青金 / C 青）两轴正交；**颜色全走 CSS 变量，禁硬编码**；白天/夜间全员可切，A/B/C 公司锁默认；个人外观存账号（切换入口见 §五 页 28）。

### 2.4 中国视觉习惯（H1~H4，[铁律]）
- **H1** 涨红跌绿；**H2** `¥`+千分位；**H3** 中文亮色、mock 真实感；**H4** 红优先给紧急/逾期、系统标签灰 ⚙。

### 2.5 工作台 = 今日动作入口（B6）
- 今日概览（逾期红/预约/周重点绿/已跟进）+ 动作条直通（写跟进主按钮 **+ 外出登记**）+ 今日安排时间轴（逾期置顶红+补单/改期直达）+ 本周重点卡片「去跟进」。

## 三、信息架构与菜单（E1~E3）

一级菜单顺序（**固定，不可改**）：
`数据看板 → 工作台 → 预约管理 → 业务关系 → 录入 → 高级搜索 → 客户管理(系统公海/部门公海) → 客户档案(公司档案/联系人档案) → 合同管理 → 工单管理 → 交付管理(客户台账) → 审批中心 → 报表分析 → 组织架构(员工/部门/产品线/角色/权限) → 系统设置(公海规则/部门规则/工作流阶段/节奏规则/数据字典)`

- **目标与进度**：`→需求§7.11`，**经理/老板可见**，入口挂在「数据看板 / 报表分析」内（不占一级菜单），个人路由 `/target`。
- **消息中心**：不做一级菜单，走**顶部铃铛**（未读角标）→ `/notifications`（见 §五 页 27）。
- **个人中心 / 外观设置**：顶部头像菜单 → `/me/appearance`（见 §五 页 28）。
- **先做 7 高频页**（工作台/看板/业务关系列表/详情/预约/录入/公海）跑通新风格再铺开（E2）。
- 侧栏子菜单可折叠、状态持久化（D1）；顶部快捷入口 ≤6 动作型（D2/D3）。

## 五、单页关键需求（必含 + 历史要求映射 + 对齐补齐）

> 标注：`A~I`=历史清单编号；`→需求§`=业务规则；`→接口API§`=接口；**[补齐]**=V1.1 对齐校正新增项。

**1 登录 /login**：账号+手机验证码/密码；亮色简洁（B2）；错误态红（B5）；登录后按角色跳看板/工作台。

**2 数据看板 /dashboard**（A/H）：4 KPI（今日新增/今日待跟进/本月签约含环比红涨H1/名下关系数）；左「今日待跟进」逾期红置顶；右状态环形图（conic-gradient）；活跃预警 3 卡（签约到期/掉公海呼吸红/新商机）；部门对比 + 销售 TOP（经理视角，被动聚合 `→需求§7.10`）。
- **[补齐] 目标进度条**（经理/老板）：主指标＝**回款额**完成率，旁挂一行「签约额 XX 万」；条下显示「**时间已过 X%**」并算领先/落后几个点——**领先＝绿、持平＝橙、落后＝红**（`→需求§7.11`）。老板看公司总条＋分部门列表；经理看部门总条＋每人列表。
- **[补齐] 周重点僵尸榜**：列出挂 ≥2 周无任何推进的周重点客户＋负责人（经理唯一硬抓手，`→需求§8.2`）。
- **[补齐] 公海超期决策待办**（经理）：超期关系列表，动作「**保留 / 删除**」（删除＝逻辑删 `deleted_at` 留痕，不自动流转 `→需求§6.3` `→接口API§4.5`）。
- **[补齐] 客户等级分布**：S/A/B/C/D，**必须标注「条」还是「家」**（默认按关系数计条；按公司去重时取全公司最高等级 `→需求§8.3`）。

**3 工作台 /workbench**（B6/A/D）：今日概览 4 数 + 动作条直通（写跟进主按钮 **＋[补齐] 外出登记**）+ 今日安排时间轴（逾期置顶红+补单/改期直达）+ 本周重点卡片「去跟进」；移动端 `→ F2`。
- **[补齐] 外出登记**（纯行政，不产生业务事件）：动作条按钮 → 弹窗只三样——**出去时间 ＋ 去干什么（一句话）＋ 可选关联业务关系**；**回来时点一下**记录回来时间即可。不做预计返回时间/交通方式/关联报销（`→需求§7.5` `→接口API§4.7`）。
- **[补齐] 快速标记批量**：勾选多个客户 → 一次性标记「未联系 / 未接电话 / 说两句挂了」；落库但**不算有效跟进、不重置掉海倒计时**（`→需求§10.2` `→接口API§4.6`）。
- **[补齐] 同类提醒合并展示**：相同类型+相同原因的提醒**合并成一条**（如"10 个客户的判死教训待补写"），点开可看是哪些客户、什么事（`→需求§10.4`）。

**4 预约管理 /appointment/:tab**（A/H）：4 Tab（今日/未来/过期红 count/未预约）；表格含距掉公海 X 天倒计时；过期行 `row-danger`；行操作写跟进/改期/完成预约（完成强制生成跟单，否则 422 `→接口API§4.7`）；默认显「过期」Tab 红色警示。

**5 业务关系列表 /relation/list**（A/C/H）：seg 视图（我的全部/跟进中/已合作/已流失/逾期未跟进 **＋[补齐] 紧迫档 5 档**）；列表含阶段彩色点、逾期红、24h 掉公海⚠、跨线 `amount_masked`、竞争徽标、**[补齐] 客户等级徽标**、**[补齐] 开发价值软档**、价值 ¥千分位 H2；行操作；分页 `→接口API§2.3`；实体可点（A1）。
- **[补齐] 紧迫档筛选与设置**：5 档 chip——**周重点（红实心）/月重点（橙）/季度跟（蓝）/长期跟（绿）/灰度（灰，默认）**；行操作/批量「标记紧迫档」（`→需求§8.2`）。
- **[补齐] 周重点闭环**：某客户挂周重点**满 2 周无推进 → 强制二选一**——① 推一把（本周必须动）② 降级（改月重点/季度跟）③ 判死（走 loss 流程）；**不接受"什么都不做"**。
- **[补齐] 等级 vs 价值两轴分开显示**：**客户等级** = S/A/B/C/D **系统自动**（滚动 12 个月回款额、部门档位）带 ⚙ 标；**开发价值** = 高/中/低/待定 **手动软档**。两者**不可混为一列、不可互转**（`→需求§8.3`）。

**6 业务关系详情 /relation/detail/:id**（A/D）：顶部信息卡；操作按钮组（写跟进/新增预约/激活/转交/创建合同禁用态+提示/创建工单 **＋[补齐] 判死 ＋[补齐] 流失**）；**8 Tab（[补齐] 由 6 扩到 8）**：基础 / 跟单 / 工作流 / **[补齐] 拜访外出** / 合同 / 工单 / 关系网 / **[补齐] 复盘**；跟单 Tab 默认展开，时间轴含逾期红分隔线 + 以 owner 分界主线/树杈（D8 `→需求§7.5`）；右侧「同公司其他关系」脱敏卡（`***` 金额、近 N 天 M 次 `→需求§13.2`）；关系网 Tab（跳槽历史 `→需求§5.1`）。
- **[补齐] 判死 / 流失**：见 §六.2 复盘弹窗。判死 → 掉回公海、**阶段保留**；流失 → 掉回公海、**阶段置 7「已流失」**（`→需求§8.1`）。
- **[补齐] 拜访外出 Tab**：本关系关联的外出登记记录（出去/回来时间、去干什么），纯行政展示、不混入跟单主线（`→需求§7.5`）。
- **[补齐] 复盘 Tab**：win / loss / churn 三类出口复盘记录与状态（草稿→批注→published），见 §六.2。
- **[补齐] 标签区**（关系级）：风险 / 业务线价值 / 协同 / coop 标签打标入口（用 §七 客户标签组件）；**coop 临时 @ 不授读权**，与正式协同（collaborator）区分（`→需求§9`）。
- **[补齐] 竞品区**：「**这单有竞品吗？**」**折叠成一行，默认"无"直接跳过**，有才展开（在用某家 / 比价中 + 一句话）；三分关系（策反/竞争/防守）**由系统推导、销售不标**；**能说才填，不点名不强求**（`→需求§11.1` `→接口API§4.4`）。
- **[补齐] 阶段推进**（工作流 Tab）：**动作驱动**——写跟单时右下角建议「当前动作 → 阶段 N」，**建议态 + 销售一键确认，绝不自动改**；限频（距上次变更 ≥3 天或跨面访/逼单里程碑才建议）；允许跳级与回退，**全部留痕**（谁/何时/从哪到哪）（`→需求§8.1`）。
- **[补齐] 成员区**：主跟单人 owner ＋ collaborator 列表（**可带有效期 `valid_until`**）＋ ask_help 临时 @ 列表（默认 7 天自动收回）；正式协同走审批、临时 @ 不授读权（`→接口API§五.2`）。

**7 录入 /entry/new**（A/E）：3 步步骤条（联系人→公司→确认）；手机号查重提示（撞库 `→接口API§4.3`）；D9 公司匹配确认阻断弹窗（列相似候选，按钮「使用已有/确认新建」，疑似重复必须给强行新建出口 `→需求§6.3`）。

**8 高级搜索 /search/advanced**（G7）：说明条「数据范围：您管辖的 N 个部门，默认第一个」；筛选（关键词/部门单选/成员/产品线/状态/时间段）；结果含所属部门+归属成员；右上「不支持导出」；空态。

**9/10 系统公海 / 部门公海**（A/D）：筛选栏；3 列卡片流（公司名/地区·规模·行业/联系人脱敏 `****1234`、进入时间、进入原因 tag、剩余 X 天倒计时）；卡片「查看详情/领取到私海」（领取幂等 `→接口API§4.5`）；未领只显概览不显跟单全文（A4.1）；部门公海差异说明条（掉落目标=本部门、仅本部门可见）。
- **[补齐] 「老客户」徽标**：派生展示（该公司档案下**存在历史合同**即显示，**不加字段**）——让新领的人一眼知道"这家我们以前做过"，别当新客重开发（`→需求§8.1`）。
- **[补齐] 入公海历史**：可查某客户每次入公海的时间/原因/原归属（`→接口API§4.5 /sea/records`）。
- **[补齐] 经理决策待办**（经理可见）：超期未处理关系 →「保留 / 删除」（逻辑删留痕），无自动删除、无自动流转。

**11~13 公司档案**（A/D）：列表显「地址是否维护」（由 address/longitude 非空派生，不新增字段 `→需求§7.3`）；详情一层抽屉（A2）简/全版分角色（§13.2）；编辑含公司档案标签（身份/制度/决策链，建档勾一次全公司共享 `→需求§9`）；经纬度人工地图拾取（非必填 `→需求§7.3`）。

**14/15 联系人档案**（A/D）：列表人员芯片 mini（D4）；详情含谈判特质（≤3，超限 422）、决策角色；悬浮卡（A5）。

**16~18 合同管理**（A/H）：整页水印；4 KPI（总额/已收款含回款率环/签单人/剩余服务）；付款流水时间轴+添加回款（凭证指 `file_asset` `→接口API§4.8`）；归属卡（签单人🔒/维护人可变更）；续约预警 90/60/30 四级；跨线合同区金额 `***` 脱敏；合同业绩分配（默认 signer100%，填给谁多少合计100% `→需求§7.6`）。

**19/20 工单管理**（A）：双分类（售后/商机）；商机↔工单双向流转（`→需求§6.4`）。

**21 客户台账 /delivery/ledger**（A/D）：产品线 Tab；表格=通用 8 列+扩展列（由字段模板驱动 `→接口API§4.10`）；到期 30 天黄警；停用字段置灰；行点开台账详情动态表单抽屉。
- **[补齐] 字段模板登记入口**（经理/管理员）：登记 **key/类型（保存后 🔒 键与类型不可改）**、停用不删；**先登记后写入**，禁止无登记 Key（`→需求§7.7` `→接口API§4.10`）。

- **[补齐] 目标进度**：完成进度按**回款额**，并列签约额（`→需求§7.11`）。
- **[补齐] 复盘三消费视图**：**赢单弹药库**（本部门可见，总经理可设全公司）/ **死因看板**（客户为什么不要我们）/ **防守清单**（哪个竞品在反挖）（`→需求§11.2`）。
- **[补齐] 等级口径标注**：凡涉 S/A/B/C/D 统计，标题必须标「**条**」或「**家**」。

**24 组织架构**（D5）：员工/部门/产品线/角色/权限 5 子页；权限矩阵页保持结构化表格不做标签化（§13.3 例外）；部门色配置、产品线固定配色。

**25 系统设置**：**5 子页（[补齐] 由 3 扩到 5）**——
- **公海规则**（L1~L4）：掉海天数；**[补齐] 改规则 7 天缓冲**（新值 7 天后生效、在途倒计时从生效日重算、**提交时预告影响客户数**；落库＝插新版本行＋旧行 disabled 停用不删）。
- **[补齐] 部门规则**（`→接口API§4.2 /org/dept-rule`）：**客户等级档位 `level_tiers`**（各部门自配金额阈值）／**灰度提醒天数 `gray_remind_days`**（只管提醒下结论，不再列为释放候选）／**谈判特质上限 `contact_trait_max`**（默认 3）／**@求助天数 `ask_help_days`**（默认 7）。
- **工作流阶段**：6 步状态机 + 阶段 7「已流失」展示配置（阶段本身固定，配展示与建议信号）。
- **[补齐] 节奏规则**（`→需求§10.3` `→接口API§4.6 /cadence-rules`）：5 类可配——新客趁热（新关系/联系人 48h 无事件）／S 级客情（已合作 S 级距上次客情 >45 天，**软提醒**）／灰度定性（灰度超 N 天未下结论）／周重点清点（每周五查本周周重点是否都动过）／**掉海预警（距掉海 ≤3 天，硬提醒永远置顶）**；**软提醒可划掉，硬提醒不行**。
- **数据字典** `dict_item`（builtin 不可删可停用 `→架构A11`）。

**[补齐] 26 目标与进度 /target**（经理/老板）：
- **三层月目标**：公司（总经理定）/ 部门（经理定）/ 个人（经理给每人定）。
- 进度条：主＝**回款额完成率**，旁挂「签约额 XX 万」；下显「**时间已过 X%**」＋领先/落后点数（**领先绿 / 持平橙 / 落后红**）。
- **目标可改但必须留痕**：标注「目标已调整过」，改前改后写 `operation_log`。
- **自上而下**：上级定，系统按人数/历史给**建议分解值**参考（避免讨价还价）。
- **铁律**：目标由管理层填，**不给销售任何填报负担**；销售只看自己，不显示他人业绩（`→需求§7.11`）。

**[补齐] 27 消息中心 /notifications**（顶部铃铛进入）：

## 六、全局交互细节

### 6.1 一层抽屉（分角色内容，§13.2）
- 经理+/总经理：完整（三档完善度 + 各业务线明细 + 联系人全号 + 跟单聚合）。
- 销售/交付/客服：简版（档案共享 + 别部门手机 `****后4` + 跟单聚合对非本人只显「近30天 N 次」）。

### 6.2 [补齐] 出口复盘弹窗（win / loss / churn，`→需求§11.2` `→接口API§4.13`）
> 原则：**复盘挂在"本来就要点的按钮"后面，不新增复盘作业**；错过时机不可补，绝不事后单独填表。

- **win 新签复盘**：转已合作（阶段→6）时**系统自动建档**（不是销售自愿建）→ 弹窗内销售可顺手填一句"赢在哪"（**可填可不填，10 秒可跳过**）→ 经理是唯一收录人+修订人，觉得有沉淀价值收进**赢单弹药库**，觉得是运气单可不收录（可注明原因）。S/A 级经理**必须逐条处理**；B/C/D 可批量，**超 30 天未处理自动不收录**。
- **loss 判死复盘**：点「判死」→ 弹窗**死因点选必填**（没真需求/输给竞品/我们没跟住/预算问题/决策链断了/说不清，**不点选 422**）；**文字当天不强制**，次日动线提醒补写（输单当天情绪最差，逼出来的全是甩锅）。提交后**关系掉回公海、阶段保留**。
- **churn 流失复盘**：点「流失」→ 选一个**主因标签**（被撬/到期未续费/服务不满/我们疏忽/客户经营变故）＋可附备注；**S/A 级高价值流失，经理必须亲自回访**（防甩锅式死因，也是挽留机会），B/C/D 级销售填标签即闭环。提交后**掉回公海、阶段置 7「已流失」**。

### 6.3 [补齐] 写跟单弹窗（唯一高频录入，`→需求§10.1/§10.2`）
> T2 目标：**10 秒完成**，绝不堆字段。

- 一句话结果（**必填，销售说的人话**）＋ 最多两个可选点选（进展、卡点）。
- **「有承诺吗？」默认无** → 有则**三快选**（我发资料 / 他给答复 / 约见面）＋ 可选时间（**默认明天**）；**不做独立录入页**。
- **卡点**：可选点选（价格/效果/信任/见不到人/时机/竞品/内部/其他），卡住时选主卡点+一句话。
- **竞品**：折叠一行「这单有竞品吗」，默认"无"直接跳过。
- **快速标记**（无效沟通专用，三选一）：未联系 / 未接电话 / 说两句挂了 —— **落库、可批量、不算有效跟进、不更新 `last_event_at`**（防点一下保号刷掉海倒计时）。卡片显「**最近 30 天尝试联系 N 次**」。
- 完成预约/拜访由**服务端强制生成**事件（422 兜底），不由前端补填。

### 6.4 悬浮卡
- 联系人（A5）：头像+姓名+职位+公司+手机脱敏+谈判特质+决策角色；「查看联系人详情」整页跳。
- 销售（A4）：头像+姓名+部门+负责产品线+联系方式；**无业绩、无名下客户数**；无下层跳转。

### 6.5 跟单聚合（D8 `→需求§7.5`）
- 默认近 1 月；**以该关系的 owner 为分界**（不是当前登录人）：owner 填的走主线、他人（协同/合并前）走树杈，两色分开不混；带图例。**经理/老板打开看到的也是"主跟单人的视角"**。

### 6.6 脱敏渲染（G4/G5 `→接口API§2.8`）
- 跨线金额 `amount_masked`；非归属手机 `phone_masked` + 「🔓 申请解锁」→ L05 审批；公海未领不返跟单全文。

### 6.7 手机号解锁流程
- 点「申请解锁」→ 弹因（可选）→ 提交 L05 → toast「已提交解锁申请」→ 经理批后限时（24h）全号，留痕 `operation_log`。

## 十一、验收标准

- 风格统一：全站走新 token，无 emoji、无旧深蓝侧栏味（B1/B4）。
- 实体可点：列表/卡片/跟单/审批/报表中无任何不可点公司名/人名（A1）。
- 抽屉只一层、悬浮卡不叠（A2/A3/A7）。
- 销售悬浮卡无业绩/客户数（A4）。
- 跟单卡显示填单人+联系人且可点（A6）。
- 脱敏三处正确：跨线金额 `***`、非归属手机 `****后4`、公海未领不显全文（G4/G5）。
- 涨红跌绿、¥千分位（H1/H2）。
- 移动端仅工作台、底部 Tab、轻面板（F1~F3）。
- 换肤 light/dark×A/B/C 生效、个人外观持久化（C1~C4）。
- 改版冒烟 0 错（I4）。
- **[补齐] 无功能悬空**：需求/接口定义的每个动作都能在页面上点到——判死/流失/复盘、目标、消息中心、节奏规则、外出登记、公海经理决策，六项**缺一不可验收**（§一.1.2 对齐铁律）。
- **[补齐] 紧迫档可设可筛**：周重点能标记、能筛选；挂满 2 周强制二选一，不接受"什么都不做"。
- **[补齐] 等级≠价值**：客户等级（系统自动⚙）与开发价值（手动软档）分开渲染，报表标「条/家」。
- **[补齐] 低摩擦录入**：写跟单 ≤10 秒（一句话 + 承诺三快选）；快速标记可批量且**不重置掉海倒计时**。
