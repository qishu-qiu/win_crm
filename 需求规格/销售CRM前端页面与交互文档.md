### 3.1 实体可点 + 一层抽屉 + 悬浮卡（A1~A7，[铁律]）
1. 公司/联系人/员工**任何位置**名称都可点（A1）；禁纯文本不可点（当前页即该实体详情页除外）。

7. 移动端悬浮卡 → 底部轻面板 `.sheet`，不叠抽屉（A7）。

## 四、信息架构与菜单（E1~E3）

一级菜单顺序（**固定，不可改**）：
`数据看板 → 工作台 → 预约管理 → 业务关系 → 录入 → 高级搜索 → 客户管理(系统公海/部门公海) → 客户档案(公司档案/联系人档案) → 合同管理 → 工单管理 → 交付管理(客户台账) → 审批中心 → 报表分析 → 组织架构(员工/部门/产品线/角色/权限) → 系统设置(公海规则/部门规则/工作流阶段/节奏规则/数据字典/签约校验清单)`

- **目标与进度**：`→需求§7.11`，**经理 / 老板可见部门层、公司层；销售可见本人层（🔒 只看自己，见 §四.2 角色矩阵）**，入口挂在「数据看板 / 报表分析」内，个人路由 `/target`。
- **消息中心**：不做一级菜单，走**顶部铃铛**（未读角标）→ `/notifications`。
- **个人中心 / 外观设置**：顶部头像菜单 → `/me/appearance`。
- **先做 7 高频页**（工作台/看板/业务关系列表/详情/预约/录入/公海）跑通新风格再铺开（E2）。
- 侧栏子菜单可折叠、状态持久化（D1）；顶部快捷入口 ≤6 动作型（D2/D3）。

1. **"服务中"的定义**（交付/客服范围）＝ **在合同服务期内**（2026-09-14 定，`→需求§4.2`）。
2. **管理员看业务数据的护栏**：一律**只读**；**所有查看动作写 `operation_log`**；**不解除脱敏**（`→需求§4.2`）——方便排障，不留"无痕看全公司"的口子。
3. **快捷入口按角色模板下发**（D3）：销售默认 4 个；经理追加「待我审批」；**交付/客服只给工单相关动作**（新建工单 / 待处理工单），不给"写跟进 / 录入客户"。⚠ 本条说的是**快捷入口这一栏**，**不是**「交付/客服全站只有工单动作」—— **台账编辑**按需求 **§7.7 明文归交付/客服**（销售只读），页面内动作不由此栏决定（2026-09-15 澄清）。
4. **实现口径**：菜单与按钮可见性由 **role ＋ `permission_matrix`** 决定；**不可见的页面不下发路由**（不是"显示了再禁用"），越权访问返回 403（`→接口API§2.2`）。

## 六、单页关键需求

> 标注：`A~I`=历史清单编号；`→需求§`=业务规则；`→接口API§`=接口；视觉/组件细节见《设计规范》。

**1 登录 /login**：**一个输入框（手机号 或 登录账号名）＋ 密码** —— 服务端判别走哪条通道，**两通道共用同一个密码**（`→接口API§5.2`）；亮色简洁（B2）；错误态红（B5）；登录后按角色跳看板/工作台。**不做"选通道"下拉**（用户不必知道自己是账号名还是手机号）。

**2 数据看板 /dashboard**（A/H）：4 KPI（今日新增/今日待跟进/本月签约含环比红涨H1/名下关系数）；左「今日待跟进」逾期红置顶；右状态环形图；活跃预警 3 卡（签约到期/掉公海呼吸红/新商机）。
- **目标进度条**（经理/老板）：主指标＝**回款额**完成率，旁挂「签约额 XX 万」；条下「时间已过 X%」＋领先/落后点数——**领先绿 / 持平橙 / 落后红**（`→需求§7.11`）。
- **周重点僵尸榜**：挂 ≥2 周无推进的周重点客户＋负责人（`→需求§8.2`）。
- **公海超期决策待办**（经理）：保留 / 删除（逻辑删留痕 `→需求§6.3`）。
- **客户等级分布**：S/A/B/C/D，**必须标「条」还是「家」**（`→需求§8.3`）。

## 九、交互规范（★）

### 9.1 hover（只做轻微背景变化）
- 表格行/列表项 hover：`--color-bg-hover`（`rgba(0,0,0,.04)`）。
- 文字按钮 hover：背景 `rgba(0,0,0,.06)`；链接 hover：`--color-primary-hover`。
- **硬禁**：hover 放大、位移、发光、阴影增强、渐变、颜色跳变。

### 9.2 点击反馈
- 所有可点元素有 active 态（背景加深/主色 `--color-primary-active`）。
- 行点击：整行可点（进详情）时行 hover 光标变手型；行内操作阻止冒泡。
- 异步操作点击后立即进入 loading（防重复点击）。

### 9.3 校验与提示
- 即时校验（blur）+ 提交校验；错误消息**指明原因与修正方式**。
- 危险操作（删除/判死）二次确认，确认按钮用 danger。

### 9.4 防抖 / 幂等
- 搜索输入 **300ms 防抖**；提交类请求带幂等键（`→接口API§2.5`）。
- 按钮 loading 期间禁用。

### 9.5 键盘与无障碍
- 焦点环：3px `--color-primary`（AntD `lineWidthFocus`）；Tab 顺序符合视觉流。
- `Esc` 关闭弹层；`Enter` 提交（表单）；下拉支持方向键。
- 对比度 ≥ 4.5:1；**不单靠颜色表意**；图标按钮带 `aria-label`。

## 十三、移动端（F1~F3 · **2026-09-18 拍板扩角色**）

> **一句话口径**：手机＝**看今天 ＋ 记一句 ＋ 点一下**（**输入与确认**）；**不做决策替代、不做横看纵比**（`→需求§十六 N3 / N8` 同一条原则：**"判"是人的活**，系统不替人下结论）。

**① 谁能用 / 用什么**（`→§4.2` 矩阵末行）

- **销售**：**今日动线** —— 写跟单（一句话 ＋ 承诺三快选）/ 快速标记 / 外出登记 / 查号拨打 / 预约 / 公海翻阅（**公海不做任何动作**，唯一例外＝改开发价值，`→需求§十六 N12`）。
- **交付 / 客服**：**工单待办版** —— 今日到期 / SLA 超时 / 待处理 ＋ 现场提交工单；服务中客户**只读**。
- **部门经理 / 总经理**：**只读 ＋ 待我审批** —— 数据看板**首屏两屏**（目标进度 ＋「需我决策」；**第 3 块起本就折叠**，`→需求§十六 N13`）＋ 客户查询（只读）＋ 审批（同意 / 驳回 ＋ 一句话）。**配置 / 报表 / 批量一律回 PC**。
- **管理员**：**不上手机**（➖）。

**② 形态**

- 375px 起，**底部固定 Tab Bar**（**Tab 组按角色下发**）；悬浮卡一律**底部轻面板**；**不叠抽屉**。
- 移动外出登记：底部 Tab「我的」→ 外出登记（出去一句话 ＋ 回来点一下）。
- **不新增页面**：以上全部＝已有页面的**窄屏可读版**（`→需求§十六 N13` 边界句）。

**③ 会议场景（会议室只有手机时）**

- **分工**：**大屏 / 台式机 ＝ 会议的共同视图**（开 PC 版看板）；**手机 ＝ 参会者自己查与记**。**不要拿 375px 投屏给全会议室看**。
- **会上四件事，全部复用已有能力**：①**查**（搜客户 → 简版抽屉：阶段 / 紧迫 / 最近跟单 / 承诺 / 号码）②**记**（写一条跟单 / 改紧迫档 / 标周重点）③**派**（建承诺：谁 · 何时 · 兑现什么）④**批**（待我审批）。
- **不为会议新增任何页面**（无「周会页 / 会议页」）—— 这是 `需求§十六 N13` 明确封的路。

## 十五、验收标准

**对齐 / 功能**
- 实体可点：列表/卡片/跟单/审批/报表中无任何不可点公司名/人名（A1）。
- 抽屉只一层、悬浮卡不叠（A2/A3/A7）；销售悬浮卡无业绩/客户数（A4）。
- 跟单卡显示填单人+联系人且可点（A6）。
- 联系方式 / 脱敏正确（**2026-09-14 重写**）：**详情一律全号**（与角色无关）；**列表 / 卡片一律 `xxx****xxxx`**（含公海）；**被 owner 上锁的联系人**，非 owner 只见「已上锁 ＋ 申请解锁」（**主号与备用号一并锁**）；跨线金额 `***`；**公海点开详情显全号可拨 ＋ 每次查看写 `operation_log` ＋ 公海页全页水印**（G4/G5）。
- 涨红跌绿、¥千分位+等宽数字（H1/H2）。
- 移动端＝**按角色下发的窄屏版**（底部 Tab ＋ 轻面板 ＋ 不叠抽屉）：销售全功能 / 交付·客服工单待办 / 经理·总经理**只读＋审批** / 管理员无；**不新增页面**（F1~F3，`→§十三`）。
- **主题：白天 / 夜间两套生效、个人外观持久化**（A/B/C 风格后置，不进 V1）。
- **无功能悬空**：判死/流失/复盘、目标、消息中心、节奏规则、外出登记、公海经理决策，六项缺一不可验收（§一.1.2 对齐铁律）。
- 紧迫档可设可筛；挂满 2 周强制二选一；等级（系统自动⚙）≠ 价值（手动软档）分开渲染、报表标「条/家」。
- 低摩擦录入：写跟单 ≤10 秒（一句话 + 承诺三快选）；快速标记可批量且不重置掉海倒计时。
